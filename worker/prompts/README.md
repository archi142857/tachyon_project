# 앱 안의 AI 프롬프트 원문

Tachyon 앱이 Claude API에 보내는 프롬프트를 고치지 않은 그대로 둔다. 부르는 곳은 [`worker/llm.js`](../llm.js) 한 곳이고, 답은 `answer` 도구 하나로 정해진 JSON 모양으로만 받는다. Haiku 5.5는 그 도구를 강제하고(tool_choice), Sonnet 5.5는 강제를 400으로 거절해서 tool_choice auto + 앞 생각 끄기(`thinking: between_tools`)로 보낸다 — 그래서 모든 프롬프트 첫 줄에 'answer 도구로만 답한다'가 있어야 한다(11-10, 공식 API primer).

## 모든 프롬프트가 지키는 규칙 (11-09 '아이디어 회의 1')

AI가 일을 부풀리지 않게 한다.
1. **쓴 말 그대로** 제목을 단다. 바꿔 쓰거나 꾸미거나 덧붙이지 않는다.
2. 요청이 없으면 일을 **쪼개지 않는다**. 메모 하나에서 일정·할 일은 하나까지.
3. **모르는 칸은 '?'**. 지어내지 않는다.

## 코드가 먼저 하는 일

- 날짜·시각(오늘·내일·다음주 화요일·3시 반 …)은 정규식으로 먼저 계산한다([3_memo_popup.js](../3_memo_popup.js)의 `findWhen`). AI는 일정·할 일·그냥 메모 중 무엇인지(kind), 이름, 장소와 오전·오후를 짐작해야 할 때의 시각만 보탠다(답 칸 4개. 11-10에 6개에서 줄임 — 배포본 실측 출력 약 157토큰이 거의 다 answer 도구 답이라 칸이 줄면 팝업이 빨라진다). AI 답이 늦거나 실패해도 팝업은 규칙만으로 뜬다.
- 날짜·시각 말이 없는 메모는 지난 일(~했다)·한 글자면 AI를 부르지 않는다. 나머지는 AI가 일정·할 일·그냥 메모를 가려(11-10 사람 "할 일만 딱 적으면 메모가 안 생김" → 컨셉 세션이 고침) 할 일이면 '할 일로 넣을까요?' 팝업(마감은 정규식이 읽은 날짜·시각). 그냥 메모는 밤 정리가 읽는다.
- 밤 정리의 마감 날짜도 정규식이 '메모를 쓴 시각' 기준으로 먼저 센다. 할 일 순서(여유 적은 순)·몰린 주 경고·브리핑 카드는 AI 없이 코드가 계산한다([4_night.js](../4_night.js)의 `rankTasks`·`crowdedWarning`).
- 팝업의 빈 시각·장소는 사용자의 일정에서 코드가 채운다([lib/known.js](../lib/known.js)): 이름이 닮은 되풀이 일정(수업)의 같은 요일 시각, 줄임말('공수2' = '공학수학 2')도 글자 순서로 맞춘다. '변경·옮김·미룸' 말이 있으면 옮길 일정도 코드가 찾는다. AI 호출과 나란히 돌고 사용자의 일정은 AI에게 보내지 않는다(토큰 그대로).
- 시간표 사진은 사용자가 확인 팝업에서 고친 뒤에만 일정이 되고, 사진은 저장·취소하면 바로 지운다.
- eTL 공지는 제목·글에 시험·휴강·보강 같은 낱말이 있을 때만 AI에게 보내고(`mightHaveDates`), 한 번 읽은 공지는 다시 읽지 않는다. 공지 글은 저장하지 않고, 찾은 일정만 `events`(source `notice`)에 남아 사용자가 고치거나 지울 수 있다.
- log 표에는 사용량(모델·ms·토큰 수)만 남기고 메모 글·답 내용은 남기지 않는다.
