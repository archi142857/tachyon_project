# 가상 학생 3사례의 GPT 사용 흐름

2026-11-07 · **설계·모의 문서**. 아래 문구와 표는 제품 대화의 설계이며 실제 GPT 응답이나 화면 캡처가 아니다. GPT 빌더 적용·실제 GPT 연결·공개는 검증하지 않았다. 숫자와 판정은 해당 입력으로 실행한 Planner 결과가 있을 때만 채운다. 계산이 없거나 실행에 실패하면 `미준비` 또는 `계산 실패`로 표시한다.

## 사례와 시작 입력

모든 학생·이수내역은 지어낸 **예시**다. 실제 학생 이름·학번·생년월일·성적·교수 이름을 예시에 넣지 않는다. 과목번호·과목명·학점·이수구분·학기·취득 상태와 입학 연도·전공 종류·입력 범위를 사용한다.

| 사례 | 구조화 입력 경로 | 확인할 경험 |
| --- | --- | --- |
| 동물생명공학전공 2학년 | `demo/inputs/animal.json` | 읽은 행 확인, 취득·수강 중·미확인 구분, 규정의 적용 연도 미확인 표시 |
| 생명과학부 복수전공 | `demo/inputs/biology_double.json` | 복수전공 적용 구분, 승인된 일부 목록의 판정과 다른 확인 필요 요건 분리 |
| 화학생물공학부 복수전공 3학년 | `demo/inputs/chemical_double.json` | 주전공 규정 오적용 방지, 중복 인정·선수·대체 규정의 확인 필요 표시 |

이 경로들은 Frontend 사례 묶음의 연결 경로다. 실제 파일·실행 결과의 존재 여부는 [검증 결과](../docs/검증_결과.md)에서 확인한다. 위 학년은 사례 설명이며 계산 코드가 이수내역으로 추정하는 값이 아니다.

대화 시작 안내 예시:

> 이름·학번·생년월일·성적을 지운 과목 표를 붙여 넣어 주세요. 과목명·학점·이수구분과 알고 있는 과목번호·학기·취득 상태를 함께 적으면 확인하기 쉽습니다. 입학 연도와 주전공·복수전공, 전체 내역인지 일부인지도 알고 있는 범위에서 알려 주세요. 모르는 값은 확인 필요로 남깁니다.

PDF 입력도 향후 같은 확인 단계를 거치도록 설계한다. 현재 구조화 입력의 정리 검증을 PDF 인식 성공으로 세지 않는다. 학교 성적 화면을 자동 조회했다고 표현하지 않는다.

이름을 지워도 과목 조합 등으로 식별 가능성이 남을 수 있다. 이름 제거가 완전한 익명성이나 서버 미보관을 보장한다고 안내하지 않는다. 이번 개발·시연에는 가상 입력만 사용한다.

## 1. 읽은 표와 입력 범위를 먼저 보여 주기

정리 결과는 [이수내역 v1](../planner/transcript_format.md)을 따른다. 원본 행을 누락하거나 반복 행을 임의 삭제하지 않는다. 확인된 취득 학점 소계는 졸업 인정 학점 합계와 구분한다.

| 행 | 입력 과목번호 / 연결 번호 | 과목명 | 입력 학점 | 입력 이수구분 | 학기 | 취득 상태 | 확인 사유 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 실행 결과의 행 | 입력 번호 / 연결 결과 또는 미연결 | 입력값 | 입력값 또는 미확인 | 입력값 또는 미확인 | 입력값 또는 미확인 | 취득 완료·수강 중·미확인 | 정리 결과의 사유를 쉬운 말로 표시 |

표 위에는 입학 연도, 전공명·종류, 입력 범위(`전체라고 사용자가 확인 / 일부 / 전체 여부 미확인`)를 표시한다. 표 아래에는 실행 결과가 제공한 취득 상태별 행 수, 확인된 취득 학점 소계, 수강 중 학점, 취득 완료이지만 합산을 보류한 행을 구분한다. 값이 없으면 0으로 채우지 않는다.

`status`는 `completed / in_progress / unknown`을 각각 취득 완료·수강 중·미확인으로 보여 준다. 누락한 상태나 알 수 없는 상태는 미확인이며, 성적이나 학기만으로 취득 완료를 추정하지 않는다. 취득 완료라고 입력한 행도 과목 연결·학점 충돌 등이 있으면 합산 보류 사유를 함께 보여 준다.

`coverage`는 `complete / partial / unknown`이다. `complete`는 사용자가 전체라고 명시했다는 뜻이며 학교에서 전체성을 검증했다는 뜻이 아니다. 응답이 없거나 일부만 제공했다면 전체로 바꾸지 않는다. 부분 입력의 소계는 `이번 입력에서 확인된 학점`이라고 표시한다.

## 2. 한 번에 확인받고 수정하기

확인 질문 예시:

> 위 표에서 잘못 읽은 행과 취득 상태를 확인해 주세요. 전체 내역인지도 함께 알려 주세요. 수정이 필요하면 행 번호와 바꿀 값만 적으면 됩니다. 모르는 항목은 미확인으로 남길 수 있습니다.

한 번의 확인 단계에 행 오류·상태·입력 범위를 모아 묻는다. 사용자가 답하지 않으면 `사용자 확인 전`을 유지하고 미입력 상태를 확정 취득으로 바꾸지 않는다. 계속 분석할 수 있는 확인된 정보의 범위를 표시하되, 사용자가 확인한 것처럼 쓰지 않는다.

사용자가 행·상태·전공·입학 연도·입력 범위를 바꾸면 정리부터 다시 실행하고 요건 판정도 다시 계산한다. 이전 결과는 이전 입력 기준임을 표시하고 최신 결과와 혼합하지 않는다. 수정에 성공했다는 문구는 재실행 성공 후에만 사용한다. 입력 오류가 나면 해당 행·필드와 필요한 형식만 안내하고 일부 행을 숨겨 성공한 것으로 표시하지 않는다.

## 3. 확인된 범위의 요건 결과 표시

요건 계산 결과가 있을 때만 아래 표를 채운다. 결과 형식은 Planner의 확정 계약과 연결하며, 이 표는 표시할 정보의 설계다. 정리 기능만 실행했다면 `입력 정리는 완료했지만 요건 계산은 미준비입니다`라고 표시한다.

| 요건 ID | 적용 전공·종류 / 입학 연도 | 요건 | 판정 | 이번 입력에서 관측한 값 | 남은 값 | 근거 | 확인 사유 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 계산 결과 ID | 계산 결과의 적용 범위 | 요건명 | 충족·남음·확인 필요 | 확인된 취득 과목·학점 등 계산값 | 계산값 또는 확정 불가 | 문서명·공식 URL·쪽/조항·적용 연도 | 규정·이수내역·중복 인정의 불확실성 |

`남은 값`은 계산이 확정한 범위만 보여 준다. `null`이나 미제공 값은 `확정 불가` 또는 `미제공`이며 0으로 바꾸지 않는다. 과목 후보 목록이 선택 조건이면 후보 전부를 필수 미이수 목록으로 표현하지 않는다. 수강 중 과목은 현재 충족분에 합산하지 않는다.

부분 입력에서 찾지 못한 과목은 `이번 입력에서 확인되지 않음`이라고 표시한다. 실제 미이수라고 단정하지 않는다. 목록 한 항목이 충족되어도 졸업 가능·졸업요건 전체 충족으로 확대하지 않는다. 항목별 학점을 더해 전체 인정 학점으로 표시하지 않는다.

Research 자료 1.0에서는 승인된 명시목록 5항목만 자동 계산 대상이다. 동물생명공학전공과 화학생물공학부 복수전공에는 자동 계산 승인 항목이 없다. 이 사례들의 확인 필요 표를 임의의 남은 졸업학점으로 채우지 않는다. 생명과학부 복수전공의 승인 목록 판정도 해당 항목의 범위로 한정한다. 최신 허용 범위는 [졸업요건 자료](../data/requirements/README.md)를 확인한다.

다전공에 같은 과목이 걸려도 중복 인정 승인으로 표시하지 않는다. 승인 학기·신청·학과 승인 등 필요한 조건이 없으면 확인 필요로 남긴다. 권장 학년·학기를 필수 선수 규칙으로 바꾸지 않으며, 대체 인정은 근거에 적힌 방향과 적용 범위를 보존한다. 근거가 없거나 확인되지 않은 요건에는 확인할 내용과 담당 학과를 표시한다.

## 4. 현재 시간표가 미준비인 경우

시간표 계산 결과가 없으면 다음과 같이 안내한다.

> 시간표 추천은 아직 준비 중입니다. 이번 결과에서는 이수내역 확인과 계산 가능한 요건만 볼 수 있습니다. 시간표·걷는 시간·추천 순위는 아직 계산하지 않았습니다.

빈 결과를 `가능한 시간표가 없습니다`라고 해석하지 않는다. 계산 미실행·계산 오류·조건에 맞는 안이 없는 결과를 구분한다. 가짜 강좌번호·시간표 3안·이동시간·동선 링크를 만들어 표시하지 않는다.

## 5. 향후 시간표 결과와 3안 비교

이 절은 **향후 연결 설계**다. 시간표 계산과 검증이 준비되면 목표 학점, 피하고 싶은 요일·시간, 출발·귀가 지점을 한 번에 선택 질문으로 받는다. 응답이 없을 때는 실제 계산기에 정의된 기본값을 표시한다. 기본값을 알 수 없으면 임의로 만들지 않는다.

| 비교 정보 | 안별 표시 기준 |
| --- | --- |
| 실제 생성된 안 | 계산기가 반환한 안만 표시. 3개 미만이면 나온 개수와 부족한 이유 표시 |
| 학기·자료 시점 | 추천 학기와 사용한 편람 학기를 구분. 지난 같은 학기 자료를 썼으면 `예상` 표시 |
| 과목·분반·학점 | 실행 결과의 식별자·학점. 각 과목이 채우는 요건과 확인 필요를 연결 |
| 요일별 시간 | 분반의 모든 수업 시간을 표시. 시간이 미정인 수업은 충돌 없음으로 확정하지 않음 |
| 시간 겹침 | 겹치는 조합은 가능한 추천안으로 표시하지 않음 |
| 이동 구간 | 출발→도착 방향, 수업 사이 빈 시간, 걷는 시간, 이동 후 여유를 함께 표시 |
| 빠듯한 구간 | 시간은 안 겹쳐도 이동 여유가 음수인 구간을 분리 표시. 계산 기준에 따른 경고 유지 |
| 강의실 미정 | 이동 미계산·확인 필요. 0분 이동 또는 충분한 여유로 표현하지 않음 |
| 한 주 이동 | 계산된 합계와 포함·누락 구간을 표시. 미정 구간이 있으면 완전한 총합으로 표현하지 않음 |
| 동선 보기 | 검증된 TT Wizard 링크만 표시. 복원한 과목·분반이 표와 일치해야 함 |

한 방향의 걷는 시간을 반대 방향에도 복사하지 않는다. 출발·귀가 구간을 포함하는지는 계산 기준과 함께 표시한다. 세 안의 우열은 실행된 비교값과 사용자 조건으로 설명하며, 미측정 시간 절감이나 만족도를 주장하지 않는다. 서로 다른 안처럼 보이도록 같은 결과를 복제하지 않는다.

## 6. 마무리와 검증 기록

마지막에는 이번에 계산한 범위, 사용자가 아직 확인하지 않은 입력, 규정의 확인 필요 목록, 시간표 준비 여부, 사용 자료의 버전·시점을 짧게 보여 준다. 계산 결과가 없으면 대화 문구 설계·수작업 기대값과 실제 실행을 구분해 적는다.

실제 검증에서는 사례 입력·수정 입력·실행 결과·독립 기대값·불일치·재현 방법을 [검증 결과](../docs/검증_결과.md)에 기록한다. 실제 GPT를 실행하지 않았다면 GPT 화면 성공으로 기록하지 않는다. 로컬 계산 통과와 GPT 연결 통과, 모의 문구와 실제 응답을 각각 구분한다.

학생이 만든 비공식 도구예요. 졸업 사정은 학과와 마이스누에서 최종 확인하세요. 다른 사람의 성적표는 올리지 마세요.
