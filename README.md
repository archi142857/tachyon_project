# tt-wizard-gpt-edition

**내가 들은 과목·소속 학과·복수전공·졸업요건을 함께 살펴보고, 수업 겹침과 강의실 이동시간을 계산해 다음 학기 시간표 3안을 제안하는 서울대 학생용 GPT를 만듭니다.**

**확장 목표는 ‘학교 로그인 → 이수내역 자동 불러오기 → 졸업요건·시간표 자동 계산 → 강의계획서 등록 알림’입니다.** 학생이 같은 정보를 반복해서 입력하지 않도록 합니다. 로그인 연동과 알림은 설계 단계이며 아직 작동하지 않습니다.

## GPT 링크와 바로 써 보기

- **GPT 링크: 준비 중.** 아직 공유된 GPT는 없습니다.
- **예시 성적표: 준비 중.** 시연을 준비할 때 [demo/](demo/)에 지어낸 학생의 PDF와 붙여 넣기용 표를 올립니다.
- 첫 시범에서는 GPT에 예시 성적표와 전공 정보를 알려 주면, 들은 과목과 적용할 요건을 확인한 뒤 **추천 시간표 3안과 추천 이유**를 받도록 만듭니다. 이후 학교 연동이 확인되면 이수내역과 전공 정보도 자동으로 불러오는 흐름을 연결합니다.
- **현재 상태: 자료 준비 완료 · 실제 시간표 추천은 준비 중.** 강좌·강의실·걷는 시간 자료를 GPT가 계산에 쓸 수 있도록 정리하고 검사했습니다. 이 준비 단계를 개발 계획에서 ‘작업 1’이라고 부릅니다.
- **바로 다음: 작업 2 — 기존 졸업요건 초안을 검증해 저장소에 반영하고, 이수내역과 대조하는 기능을 만듭니다.** 최신 완료 범위·다음 산출물·확인 사항은 [현재 상태](docs/현재_상태.md)에서 관리합니다. 다른 AI가 이어서 작업할 때도 [작업 지침](AGENTS.md)과 이 문서부터 읽으면 됩니다.

**학생이 만든 비공식 도구예요. 졸업 사정은 학과와 마이스누에서 최종 확인하세요. 다른 사람의 성적표는 올리지 마세요.**

## 시연 그림

**준비 중.** 실제 GPT가 지어낸 학생의 자료로 응답한 화면을 시연 단계에서 공개합니다.

## 무엇을 해결하나요?

학생은 다음 학기 시간표를 짤 때 ‘졸업하려면 무엇을 더 들어야 하는지’, ‘복수전공 과목과 시간이 겹치지 않는지’, ‘수업이 끝나고 다음 강의실까지 갈 수 있는지’를 함께 고민합니다. 이 조건들을 한 번에 살펴보고 **내 상황에 맞는 시간표를 고를 수 있게 하는 것**이 목표입니다.

**내 이수내역·전공 정보 → 남은 졸업요건 확인 → 다음 학기 과목 선정 → 수업 겹침·이동시간 계산 → 시간표 3안 비교**

학생이 하는 일은 **학교 로그인, 불러온 정보 한 번 확인, 시간표 선택** 정도로 줄이는 것이 목표입니다. 선택한 시간표의 강의계획서도 자동으로 모으고, 알림을 한 번 켜면 등록 여부를 반복해서 확인하게 합니다. 내부 브라우저에서 학교 로그인 화면을 여는 방식은 원하는 사용 흐름이며, 학교에서 지원하는 연결 방법과 실제 가능 여부를 확인해야 합니다. [자동화 설계](docs/자동화_흐름.md)에 단계별 처리와 실패했을 때의 동작을 정리했습니다.

| 함께 살펴볼 것 | 시간표에 어떻게 반영하나요? |
| --- | --- |
| 이미 들은 과목과 취득 학점 | 남은 요건을 찾고 이미 채운 항목을 구분합니다. |
| 입학연도·학과·주전공·복수전공 | 학생에게 적용되는 교양·전공 졸업요건을 고릅니다. |
| 필수과목·권장 이수 시기·먼저 들어야 하는 과목 | 다음 학기에 들을 과목의 우선순위를 정합니다. |
| 다음 학기 개설 강좌와 수업 시간 | 시간이 겹치는 조합을 제외합니다. |
| 강의실 위치와 수업 사이 빈 시간 | 걸리는 시간과 이동 후 남는 여유를 계산하고, 빠듯한 구간을 표시합니다. |
| 원하는 학점·피하고 싶은 시간·출발 지점 | 학생이 알려 준 조건을 시간표에 반영합니다. |

결과에는 **시간표 3안, 과목별 추천 이유와 채우는 요건, 이동에 걸리는 시간, 빠듯한 구간, 근거 자료**를 함께 보여 줍니다. 확인되지 않은 졸업요건과 강의실은 ‘확인 필요’로 남깁니다. 자세한 입력과 결과는 [서비스 흐름](docs/서비스_흐름.md)에 정리했습니다. 이 표는 완성 목표이며, 현재는 자료 준비 단계입니다.

과목마다 강의계획서가 올라오는 시점도 다릅니다. **관심 과목의 강의계획서를 한곳에서 보고, 아직 없는 계획서가 등록되면 알림을 받는 기능**을 추가로 계획합니다. 과목별 등록 상태와 마지막 확인 시각을 보여 주어 여러 과목을 일일이 다시 확인하는 수고를 줄이려 합니다. 현재는 [기능 설계](docs/강의계획서_모아보기와_알림.md)를 정리한 상태이며, 실제 조회와 알림은 아직 구현하지 않았습니다.

## ChatGPT Edu를 어떻게 활용했나요?

Codex에 작업 지침과 자료 형식을 주어 공개 저장소 구조, 자료를 읽고 정리하는 코드, 자동 검증을 만들었습니다. [받은 프롬프트 원문](prompts/00-시작.md), [최종 목표를 정리한 요청](prompts/00c-서비스-목표.md), [작업 기록](docs/작업_기록.md)을 공개합니다. ChatGPT 웹에서 사용한 딥 리서치 프롬프트와 결과는 작업 2에서 별도로 기록할 예정입니다.

| 원래 있던 것: TT Wizard | 이번에 Codex로 새로 만든 것 |
| --- | --- |
| 학기별 수강편람 기록, 방향별 걷는 시간, 건물 위치 | 학사 강좌만 추출하고 교수 열을 버리는 GPT용 자료 생성 코드 |
| 분반 조합을 찾아 동선을 보여 주는 시간표·지도 서비스 | 입력 형식·교수 정보 제거·자료 수·갱신 오류를 검사하는 테스트 |
| [기존 코드](https://github.com/Archi142857/tt-wizard)와 [기존 웹](https://archi142857.github.io/tt-wizard/) | 심사위원용 README, 프롬프트 기록, 출처·자료 조건 정리 |

졸업요건 대조와 시간표 3안 계산을 GPT에 연결하는 작업은 이후에 진행합니다. 기존 TT Wizard의 기능을 이번에 새로 만든 성과로 세지 않습니다.

## 어떤 효과가 있나요?

- **확인한 결과:** 교수 정보가 없는 학사 자료, 135개 지점의 좌표, 방향별 걷는 시간 18,090행을 생성하는 절차와 검증을 마련했습니다. 최신 실행 수치는 [작업 기록](docs/작업_기록.md)에 남깁니다.
- **기대효과:** 학생이 이수내역과 전공 정보를 알려 주면, 졸업에 필요한 과목과 실제 이동을 함께 고려한 시간표 후보를 비교할 수 있습니다. 여러 학과의 요건과 강좌를 따로 찾아 조합하는 수고를 줄이려 합니다.
- **추가로 줄이려는 수고:** 관심 과목의 강의계획서가 올라왔는지 반복해서 확인하는 일. 모아보기와 등록 알림은 설계 단계이며 효과는 아직 측정하지 않았습니다.
- **자동화 목표:** 이수 과목·전공 정보를 반복해서 입력하는 일과 단계마다 따로 실행하는 일을 줄입니다. 로그인 연동의 가능 여부와 실제 절감 효과는 아직 검증하지 않았습니다.
- **아직 측정하지 않은 것:** 사용 시간 절감, 졸업요건 판정 정확도, 실제 학생의 만족도. 측정 전 수치는 성과로 제시하지 않습니다.

## ‘작업 1’은 무엇이고, 다음에는 무엇을 만드나요?

‘작업 1~5’는 이 프로젝트를 만드는 순서입니다. **작업 1은 시간표 추천에 필요한 강좌·강의실·걷는 시간 자료를 모아, 계산에 쓸 수 있게 정리하고 검사하는 준비 단계**입니다. 심사위원이 과정을 살펴볼 수 있도록 소개 문서, 프롬프트 원문, 출처도 함께 정리했습니다.

| 개발 순서 | 하는 일 | 끝나면 무엇이 가능해지나요? | 현재 상태 |
| --- | --- | --- | --- |
| **1. 자료 준비** | 강좌·건물·걷는 시간·개설 이력을 정리하고 검사합니다. 소개 문서와 프롬프트도 기록합니다. | 추천 계산에 쓸 기초 자료와 검증 방법이 갖춰집니다. | **완료** |
| **2. 개인별 졸업요건 확인** | 이수내역과 입학연도·학과·복수전공의 요건을 대조합니다. | 더 들어야 할 과목과 남은 학점을 근거와 함께 알 수 있습니다. | **다음 과제** · 별도 조사 초안 검증·반영 필요, 대조 기능 미구현 |
| **3. 다음 학기 시간표 계산** | 필요한 과목을 고르고 수업 겹침·걷는 시간·이동 여유를 계산합니다. | 내 조건에 맞는 시간표 3안과 추천 이유를 비교할 수 있습니다. | 미구현 |
| **4. GPT로 연결** | 학생과 대화하며 자료를 읽고 계산하도록 GPT를 설정합니다. | 학생이 자료를 올리고 GPT에서 추천 결과를 받을 수 있습니다. | 미구현 |
| **5. 시연과 결과 확인** | 지어낸 학생의 자료로 처음부터 끝까지 사용하고 결과를 대조합니다. | 심사위원이 직접 체험하고, 확인된 효과와 한계를 볼 수 있습니다. | 미구현 |

‘작업 6’은 GPT Actions라는 연결 방식의 선택 사항이며, 도입 여부는 아직 정하지 않았습니다. 이번에 추가한 자동화 목표를 구현할 방식은 별도로 확인합니다. 개발용 세부 항목은 [작업 목록](docs/작업_목록.md), 실제 진행 내역은 [작업 기록](docs/작업_기록.md)에서 볼 수 있습니다.

**추가 요구사항: 강의계획서 모아보기·등록 알림.** 기존 작업 1의 강좌 자료에는 계획서 등록 여부가 없습니다. 공식 조회 경로와 확인 주기·알림 수단을 확인한 뒤 구현 범위를 정합니다. 이 기능의 추가가 작업 6의 GPT Actions 사용을 결정한 것은 아닙니다.

**추가 요구사항: 로그인 후 자동 진행.** 이수내역을 불러온 뒤 요건 대조·시간표 계산·계획서 목록 구성까지 이어지게 설계했습니다. 실제 마이스누 자동 조회는 [기존 지침](AGENTS.md)의 정보화본부 회신 조건이 남아 있습니다. 현재 이 연결을 구현하거나 실제 학생 계정으로 검증하지 않았습니다.

## 자료 다시 만들기

Python 3.11 이상이 필요합니다. 생성 코드는 파이썬에 기본으로 포함된 기능만 사용합니다. 저장소 폴더에서 실행하세요.

```sh
python scripts/sync_ttwizard.py
```

기본 원본은 `D:\프로젝트 폴더\코딩\TT Wizard\tt-wizard`입니다. 이 폴더에서 허용된 자료만 읽고, 원본이나 형제 폴더는 수정하지 않습니다. 다른 PC에서는 로컬 사본 경로를 지정하거나 아래 공개 주소를 쓸 수 있습니다.

```sh
python scripts/sync_ttwizard.py --source "다른 PC의 TT Wizard 경로"
python scripts/sync_ttwizard.py --source https://raw.githubusercontent.com/Archi142857/tt-wizard/main/ --as-of-year 2026
```

`data/offerings/`, `walk.csv`, `buildings.csv`, `likelihood.csv`와 원자료 확인 기록은 스크립트로만 갱신합니다. 원자료 확인 기록에는 파일이 바뀌었는지 대조할 수 있는 SHA-256 값(파일 내용을 계산한 식별값)을 남깁니다. 교수 열, 원본 메모, 개인 폴더 경로, 높이 자료는 결과에 넣지 않습니다.
