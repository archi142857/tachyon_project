생명과학 복수전공 `biology-double-R05`는 취득 관측 1과목·2학점, 수강 중 실험2, 미확인 특수연구1로 반환됐다. `observed_deficit`은 2과목·3학점이지만 `remaining=null`이다. 화면에서는 확정 남은 학점으로 옮기지 않는다. 화생 주전공 승인 항목은 화생 복수전공 결과에 포함되지 않았다.

별도 수정·경계 검사에서는 특수연구1 취득 정정 후 3학점, 실험2까지 취득 정정 후 5학점을 확인했다. 일부 입력·다전공 상태는 계속 확인 필요다. 생명과학 주전공 하나와 전체라고 명시한 가상 경계 입력에서는 단일 목록이 5학점일 때 충족, 실험2가 수강 중이면 2학점·1과목 남음으로 반환됐다. 전체 졸업 상태는 계속 미판정이다.

## 검증 방법과 결과

기대값은 [독립 기대값](../demo/독립_기대값.md)에 Planner 실행 전에 고정했다. 계산 출력에서 기대값을 생성하지 않았다. 보조 검토에서 Research 승인 5목록·적용 전공·학점·수동 항목 경계를 따로 확인했다. Frontend는 생명과학 공식 교과과정과 2025-01-10 공지를 재조회했고, 다른 학과의 공식 규정을 전면 재검증하지 않았다.

## 작업 3 독립 검사 준비 — 첫 통합 이후

기준 커밋09b4ecf 이후 Planner가 `planner/timetable_format.md`를 공유하고 독립 준비를 요청했다. [시간표 경계 입력](../demo/timetable_boundary.json), [독립 수작업 기준 F01~F15](../demo/시간표_독립_기대값.md), `tests/test_end_to_end.py`의 추가14개 검사를 작성했다. 기존 T01~T08을 집 출발·귀가 포함 범위와 정확히 전년도 같은 학기 조건으로 구체화했다.

새 검사는 방향별 비용52.26/42.94, 맞닿은 수업시간의 이동 부족, 모든 회의의 충돌, 미정 건물·누락 방향의null/부분합계, 실제0~3안, 회피조건, 예상학기와 표준라이브러리 독립 링크복원, 누락 이력·권장학년 분리, 탐색 한도, 참고·선수·인정·학점충돌 경고의 최종 전파를 다룬다. 수작업 검토도 별도로 받았다.

**이 준비 시점에는 새14개를 실행하지 않았다.** Planner는 엔진·보고 구현 중이므로 통합 준비 통지를 기다리라고 요청했다. 파일이 생겼다는 사실만으로 완료를 표시하지 않는다. 이전 요건 범위만 실행한 결과는 `12 passed, 14 deselected in 1.40s`다.14개 제외는 성공·통과로 세지 않는다. 실행 명령은 `python -m pytest tests/test_end_to_end.py -k "not timetable" -q`이며 기존과 같은 앱 Python·전용 테스트 도구로 수행했다.

이 변경은 가상 검증 준비다. 실제 시간표 엔진 통과, 기존3학생의 시간표 추천, 실제 GPT·지도 웹페이지 실행을 완료했다고 주장하지 않는다. 요청·반환형 협의·후속 조건은 [Frontend-07](../prompts/Frontend-07-시간표-독립검증.md)에 원문 기록했다.

## 작업3 독립 실행 완료 — 2026-11-07, 기준09b4ecf 이후

Planner의 통합 API 마감 통지를 받은 뒤 사전에 작성한14개 시간표 검사와 기존12개 요건 검사를 실행했다. 최초 **26 passed, 1.77초**, 당시 전체 **428 passed, 9 subtests passed, 12.13초**였다. 계산 코드 오류는 발견하지 못했다.

읽기전용 보조 검토에서 구간별 양수/음수 여유, 회피조건의 탐색 완료 여부, Markdown의 각 경고 문구를 더 직접 검사하면 검증 범위를 명확히 할 수 있다는 의견을 받았다. 기대값·계산 코드는 바꾸지 않고 기존 검사에 확인문만 추가했다. 보강 후 **26 passed, 3.15초**, 건너뜀 없음. 이 실행 전후의 계산 코드·입력·검사 파일 해시가 같음을 확인했다. 전체428개 결과는 보강 전 실행 시점이며, 이후 보강한26개는 별도 재실행 결과다.

별도로 `python demo/run_timetable_local.py`를 실행해 고정 모의5상황을 계산하고 [실제 실행 JSON](../demo/timetable_verification.json)에 결과·Markdown·관련 파일 SHA256을 저장했다. 실행 중 파일이 바뀌면 저장하지 않도록 검사한다. 실제 학생이 아닌 `EXAMPLE.FRONTEND.A/B` 모의 강좌이며 링크를 실제 수강지도 성공 사례로 사용하지 않는다.

| 모의 상황 | 걷기 합계 | 이동 부족 | 비용 | 판정 범위 |

정·역방향의 집 출발·귀가를 포함한 합계다. 비용은 걷기+2×부족분이며 단위는 분 기준 점수다. 산술은 수작업 기대값과 일치했다. F01~F15는15개 검증 기준이며 테스트 개수14개와 동일한 단위가 아니다. 몇 기준은 한 테스트에서 함께 검사한다.

확인한 경계: 두 번째 회의의 충돌, 방향자료 누락 시 역방향 대체 금지, 전체null과 알려진 부분합계 구분,0~3안·조합 중복 금지, 회피요일/시간, 전년도 같은 학기만 대체, 개설빈도 창과 권장학년 분리, 탐색 한도, 선수·인정·학점충돌 경고의 선택분반/계획/최종JSON·Markdown 전파, 예상 학기·분반의 독립 링크 해독.

이번14개로 확인하지 않은 범위: 건물은 확인되나 방만 미정인 개별 경계, 링크j/z 두 형식 각각의 강제 실행, 실제 지도 페이지 열림, 실제 편람 전체를 쓴3학생의 시간표 추천, 실제 GPT·개인정보·학교 연결·전체 졸업 사정. 독립 해독기는j/z를 모두 지원하지만 이 사실만으로 두 형식을 각각 검사했다고 세지 않는다. 다른 담당의 단위검사 범위는 해당 담당 기록을 따른다.

검사·실행기·자료 외 계산 코드는 수정하지 않았다. 이전 `demo/results/`의3학생 요건 시연은 재생성하지 않았으며 별도 파일로 유지했다. 이번 요청·검토·보고는 Frontend-08에 AI 내부 기록으로 남긴다.

## 다음 검증

1. 작업3 독립26개 실행 결과를 Planner·Concept·Document에 전달한다. 관련 코드 변경이 생기면 해당 검사와 실행 해시를 다시 확인한다. Frontend는 커밋·푸시하지 않는다.

3. Integrations 모의 API를 이용한 전체/부분/만료 및 계획서 최초 확인·새 등록·실패 복구·끄기 표시 검증은 후속 범위로 둔다. 실제 연결·발송으로 표시하지 않는다.
4. 실제 GPT 적용·시연은 계산 묶음과 해당 Edu 계정의 이용 가능 조건 확인 이후 별도 실행한다. 현재 제품 변경 안내와 계정 적용 여부는 Legal 인수인계를 먼저 확인한다. 실제 공개·빌더 변경은 이번 배정에 포함되지 않는다.
