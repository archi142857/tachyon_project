## 1. 무엇을 만드나

**Tachyon Project**(11-09 정한 프로젝트 이름. 앱 이름도 Tachyon) = 서울대생용 세컨브레인 웹앱. 처음 임시 이름은 NGS(Next Generation Second-brain)였고 11-09 저녁에 모두 Tachyon으로 바꿨다. 그 전 커밋 메시지·소통판 글·프롬프트 원문에는 NGS가 그대로 남아 있다.
- eTL 과제, 캘린더, 시간표 사진, 메모를 모아서 가운데의 '달력 + 할 일'을 돌린다.
- 화면은 적게: 할 일 3개 · 주간 달력 · 메모(나와의 채팅처럼 쓰는 칸). 일정처럼 보이는 메모는 바로 '이대로 저장할까?', 할 일 메모는 '할 일로 넣을까요?' 팝업(11-10).
- 밤 01:30에 메모를 정리해 아침 브리핑을 만든다(먼저 할 것, 미룰 것).
- 목표는 빨리 만들어 팀이 매일 쓰면서 버그·불편·추가할 것을 뽑아 고치는 것. 계획의 '피드백 고리'가 핵심이다.

## 4. 확인한 사실

- **eTL은 토큰 없이 받는 ICS 주소가 있다.** eTL(LearningX = Canvas)의 `GET https://myetl.snu.ac.kr/api/v1/users/self/profile`(헤더 `Authorization: Bearer <eTL 액세스 토큰>`) 응답의 `calendar.ics`가 그 주소다. 11-09에 주소만으로 받아짐(3.3초), **마감 있는 과제만** 들어 있다. 마감 없는 과제·공지·강의자료는 없다 → 공지(시험·휴강)는 3단계에서 토큰으로.
  - eTL 웹 화면에서 이 주소를 찾는 길은 아직 확인하지 않았다(첫 설정 안내에 필요).
  - 이 주소는 아는 사람 누구나 그 학생의 과제를 볼 수 있는 **비밀값**이다. 저장소·로그·캡처에 넣지 않는다.
- **eTL 개인 액세스 토큰으로 Canvas API가 된다**(11-10 팀원 확인 — dhsrua555 사람이 11-02부터 자기 토큰으로 씀): 강의·과제와 제출 여부·공지·파일·주차. 만드는 곳은 eTL → 계정 → 설정 → 승인된 통합 → '+ 새 액세스 토큰'. 파일 주소에는 검증값이 붙어 토큰 없이 받아진다(비밀값처럼). 되는 호출과 지킬 것은 [계획](계획.md) 3단계 'eTL API 연결'의 '11-10 사전 확인'. 학교 규정은 아직 모른다(eTL 담당: 학부대학 디지털교육혁신센터).
- **Cloudflare Worker에서 eTL ICS가 받아진다**(11-09): 요청 3번·Cron 1번 모두 200, 1.1~4.3초. Worker가 미국 서버(LAX·SJC)에서 돌아도 막히지 않는다(무료 플랜은 한국 요청도 미국 서버로 갈 때가 많다).
- **Cloudflare 계정 = dhsrua555 사용자 것**(11-09). 배포 주소 https://tachyon.tachyon-project.workers.dev, D1 `tachyon`(아시아). 배포는 아직 손으로(`npm run deploy`, 로그인은 `npx wrangler login`). 팀원은 멤버로 초대받아야 배포·로그를 볼 수 있다.
- **D1 무료 한도에서 걸리는 건 용량(DB당 500 MB, 사용자당 약 1 MB)이 아니라 하루 쓰기 10만 줄이다.** 수집기는 바뀐 줄만 쓴다(계획 1단계 수집 항목).
- 아직 확인 못 한 것: Haiku 팝업이 1초 안에 오는지.
- 코드: 뼈대만 있다(`wrangler.toml`, `worker/index.js`의 `/api/health`, `web/index.html` 빈 화면, `schema.sql` 초안).

## 5. 일하는 방식

- **할 일:** [계획](계획.md)의 체크박스가 원본. 시작 전에 `← 먼저:`가 끝났는지 보고, 끝나면 `— 끝:` 기준을 실제로 확인한 뒤 `[x]`와 날짜를 단다. 문서만 쓰고 '완료'로 표시하지 않는다.
- **기록(AGENTS.md 규칙):** 사람이 준 요청마다 `prompts/Tachyon-NN-짧은-제목.md` 한 파일(제목, 날짜, 도구, 목적, 원문 그대로, 결과 요약, 바뀐 파일). `prompts/README.md` 목록에 한 줄, `docs/작업_기록.md`에 날짜별 몇 줄.
- **개인정보:** 실제 일정·eTL 주소·토큰·학번·이름·성적은 저장소·테스트·캡처에 넣지 않는다. 예시는 지어낸 자료로 만들고 '예시'라고 적는다. API 키는 Cloudflare 비밀값에만.
- **코드:** 사람이 바로 읽게. 파일 하나 = 할 일 하나, 흐름 순서대로 번호(`worker/1_login.js`, `2_collect_ics.js` …), 설정은 `wrangler.toml` 한 곳, README에 흐름과 실행법. 쓸데없는 추상화를 하지 않는다.
- **앱 프롬프트 규칙(회의):** AI가 일을 부풀리지 않게 한다. 사용자가 쓴 말 그대로 제목을 달고, 요청이 없으면 일을 쪼개지 않고, 모르는 칸은 '?'로 둔다. 앱 프롬프트 원문은 `worker/prompts/`에 두고 `prompts/README.md`에서 링크한다.
- **알림은 적게:** 푸시는 아침 브리핑 하루 1번만.
- **보고:** 끝날 때 한 일, 확인한 방법, 남은 일, 다음 할 일을 쉬운 말로 적는다.
