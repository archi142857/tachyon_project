archi142857 노트북에서는 Claude 세션 여러 개로 나눠 일한다. 이 문서는 **우리 세션끼리** 부딪히지 않게 하는 규칙이다. 팀 규칙이 먼저다: [AGENTS.md](../../AGENTS.md) 맨 위 'Tachyon Project' 칸과 [소통판](소통.md) 규칙(시작할 때 `git pull` → 소통판 새 글, 일을 맡을 때 [계획](계획.md) 그 줄에 `— 작업 중: archi142857 MM-DD`, 끝나면 `[x]`·소통판 글·pull → 커밋 → 푸시).

세션 나누기와 이 규칙은 **컨셉** 세션이 맡는다. claude.ai 프로젝트 안의 세션은 프로젝트 문서 `Tachyon_작업_방식.md`(같은 내용)를 먼저 읽는다.

## 2. 서버 ↔ AI ↔ 화면 약속 (제안, 소통판 합의 대상)

- `worker/index.js`는 주소만 나누고 기능은 번호 파일에 둔다(팀원 뼈대의 방식). 제안 주소: `/api/login*` → 1_login, `/api/feeds*` → 2_collect_ics, `/api/memo*` → 3_memo_popup, `/api/briefing*` → 4_night, `/api/timetable*` → 5_timetable_photo, `/api/feedback*` → 6_feedback, `/api/tasks*`·`/api/events*` → 7_items, `/api/calendar*` → 8_calendar_feed(11-09 추가, '할 일 3개' 순서는 AI가 `4_night.js`에서 함수로 내놓고 7_items가 가져다 씀).
- 번호 파일은 `export async function handle(request, env, ctx, user)`를 내고, Cron이 필요하면 `export async function scheduled(event, env, ctx)`도 낸다. 로그인 사용자 확인은 `worker/lib/auth.js`의 `getUser(request, env)`.
- Cron 제안: `*/15 * * * *` → 수집, `30 16 * * *`(한국 01:30) → 밤 정리.
- Claude API 호출은 `worker/llm.js` 한 곳. 앱 프롬프트 원문은 `worker/prompts/`.
- 시각은 `schema.sql` 머리말을 따른다: ISO 8601에 `+09:00`(예: `2026-11-13T15:00:00+09:00`), 종일 일정은 날짜만. 응답은 JSON.

## 3. 쪽지

- **팀원 쪽 AI와:** 저장소의 [소통판](소통.md)만 쓴다. 보낸 사람은 `archi142857(Claude·<세션>)`.
- **우리 세션끼리:** 팀 공유 구글 드라이브 'Tachyon Project' / `멀티 세션용 공유 폴더`(비공개, 처음 이름 '세션소통'). 규칙과 폴더 id는 그 안의 `README.md`. 요약:
  - 세션은 서로를 못 깨운다. 사용자가 "쪽지 확인해"나 "공유 폴더"라고 하면 그때 자기 받은편지함을 본다. 새 일을 시작할 때도 한 번 본다.
  - 쪽지 하나 = 파일 하나: `받은편지함/<세션>/YYMMDD-HHMM_<보낸 세션>_<짧은-제목>.md`. 첫 줄 `# 제목`, 본문은 짧게 반말. 고치지 않고 새 쪽지로 더한다. 답장은 제목 앞에 `답-`.
  - 처리한 쪽지는 받는 세션이 자기 `처리됨/`으로 옮기고 설명에 `끝 (한 일)`을 단다.
  - 다른 세션에 쪽지를 남긴 답은 맨 끝에 `공유폴더: 서버, AI`처럼 한 줄.
- **사용자(archi142857)에게 필요한 것은 컨셉이 모은다**(11-09 사용자 지시): 권한·대답·손이 필요한 일(계정·결제·비밀값 넣기·승인·결정·확인)은 사용자에게 바로 묻지 않고, 컨셉 받은편지함에 `YYMMDD-HHMM_<세션>_사용자-<짧은-제목>.md`(무엇을·왜·어떻게·언제까지)로 보낸 뒤 막히지 않는 다른 일을 한다. 컨셉이 모아 사용자에게 한 번에 알리고 답을 전한다. 팀원 쪽이 소통판에 사람에게 묻거나 부탁한 것도 컨셉이 모은다. 도구가 띄우는 권한 창은 예외.

## 4. 레포에 올리기

- 맡은 경로만 고치고, 팀 규칙대로 `git pull`(rebase) 뒤 main에 커밋·푸시한다. 강제 푸시·남의 변경 되돌리기는 하지 않는다. 테스트가 있으면 돌리고 올린다.
- 커밋 작성자는 사용자 이름(앞 커밋과 같은 이름·이메일), 커미터는 그대로. 메시지는 `[Tachyon] 한글 요약`, 빈 줄, 한글 글머리표, 맨 끝 Co-Authored-By 줄.
- 프롬프트 기록은 팀원 번호(`Tachyon-NN`)와 겹치지 않게 `prompts/Tachyon-<세션>-NN-제목.md`로 새 파일만 만든다. 목록 `prompts/README.md`와 `docs/작업_기록.md`는 컨셉이 모아 고친다.
- GitHub Desktop Pull origin 부탁은 각 세션이 따로 하지 않는다. 필요하면 컨셉에 쪽지(3절).

## 5. 같이 지킬 것

- 비밀값(Claude API 키, OAuth 비밀값, eTL 캘린더 주소·토큰, 암호화 키)은 채팅·쪽지·파일·레포에 적지 않는다. Cloudflare 비밀값(`npx wrangler secret put`)에만 둔다.
- 실제 일정·실명·학번·이메일은 레포·테스트·캡처·이슈에 넣지 않는다. 그런 파일은 팀 드라이브에 두고 소통판엔 `드라이브에 올림: 파일 이름`만.
- 앱 프롬프트 규칙: 쓴 말 그대로 제목, 요청 없으면 쪼개지 않음, 모르는 칸은 '?'. 알림은 아침 브리핑 하루 1번만.
- 디자인은 시안 3개를 그림으로 짧게 먼저 보여 주고, 사용자가 고른 것만 완성한다.
- 할 일은 `— 끝:` 기준을 실제로 확인한 뒤 끝으로 친다. 끝낼 때 한 일 · 확인한 방법 · 남은 일 · 다음 할 일을 쉬운 말로 적는다.
