## 오늘 확인한 것 (11-09)

- **eTL은 토큰 없이 받는 캘린더 주소(ICS)가 있다.** 프로필의 `calendar.ics`. 시험: 토큰 없이 받아짐(3.3초), 마감 있는 과제만 들어 있다(마감 없는 과제·공지·강의자료는 없음).
  → 1단계는 이 주소 하나로 과제 마감을 받는다. 공지(시험·휴강)·강의계획서는 토큰이 필요하니 3단계.
- 그래서 **모든 캘린더를 ICS 주소로 읽는다**: 구글 '비공개 주소(iCal 형식)', 애플 '공개 캘린더' 링크, 노션 캘린더는 구글 것을 씀, 삼성은 구글 계정 동기화 → 구글 주소.
  → 구글 캘린더 권한(검증 몇 주)을 기다리지 않고 시작한다. 수집기도 하나.
- **구글 로그인은 기본 정보(이름·이메일)만** 받는다 → 앱 검증·테스트 사용자 명단·7일 만료가 모두 필요 없다.
  → 단, 구글 쪽 설정을 '앱 게시'로 바꾸기 전('테스트' 상태)에는 명단에 넣은 계정만 들어온다. 게시는 4단계 줄, 그 전 명단은 사람에게 받는 중.
- **서울대 2026-2학기: 개강 9/1, 종강 12/14(월), 보강기간 12/15~12/21**(서울대 학사일정). 시간표 사진의 '학기 끝' 기본값(지금 12-20 짐작)은 AI 세션에 쪽지로 알림.

## 스택 (하나로)

- **Cloudflare (11-09 확정)**: Workers(API + 화면 파일) · D1(DB) · R2(시간표 사진) · Cron(ICS 15분마다, 밤 정리 01:30 KST). 회의 때 만들던 로그인 작업을 그대로 잇는다. 무료로 시작, 요청당 CPU 10 ms 한도에 걸리면 Workers 유료($5/월).
- **화면**: PWA. 로그인 작업에서 쓰던 틀 그대로(없으면 Vite + React). 폰은 '홈 화면에 추가'.
- **앱**: 같은 `web/`를 [Capacitor](https://capacitorjs.com)로 감싼다(코드 하나). 앱에서만 되는 것: 폰 캘린더 직접 읽기·쓰기(아래). 아이폰 앱 빌드는 Mac + Xcode가 있어야 하고, 팀 배포(TestFlight)는 Apple 개발자 계정 연 99달러. 안드로이드는 APK를 바로 나눠 줄 수 있다.
- **AI**: Claude API. 즉시 팝업 = Haiku 5.5, 밤 정리·브리핑·시간표 사진 = Sonnet 5.5. 호출은 `worker/llm.js` 한 곳에. 지출은 팀원 구독에 딸린 월 API 크레딧 $200 안에서만(넘으면 멈춤, 11-10 확인).
- **공모전 규정 (11-09 확인, [공모전](공모전.md))**: 신청서가 'ChatGPT Edu를 어떻게 활용했나'를 묻고 9월 수상작도 모두 ChatGPT Edu·Codex로 설명한다. 11-09 팀 합의: ChatGPT Edu에서 Tachyon 부르기 = MCP 서버(3단계, 새 GPT 만들기는 9/25로 끝남), 앱 안 AI는 Claude 그대로. ## 캘린더 직접 읽기 — 웹과 앱 (11-09 조사)

| 켜는 곳 | 기기 캘린더를 직접 읽나 | 그래서 |
|---|---|---|
| 웹(PWA, 폰·PC 모두) | **안 된다.** 브라우저에 캘린더 API가 없고, Capacitor 캘린더 플러그인도 '웹 불가' | ICS 주소(지금 계획) |
| 안드로이드 앱 | **된다.** 공식 `@capacitor/calendar`, 권한 READ_CALENDAR(쓰기는 WRITE_CALENDAR, 플러그인에 들어 있음) | 앱을 열 때 폰 캘린더 → 서버로 올림(`source = device`). 켜면 Tachyon 일정을 폰 안 'Tachyon' 캘린더에 씀(11-10) |
| 아이폰 앱 | **된다.** 같은 플러그인, iOS 17부터는 '전체 접근'을 받아야 읽힘(쓰기 전용 권한으론 못 읽음) | 같음 |
| 데스크톱 앱 | 사실상 안 된다(맥만 길이 있고 윈도우는 확인 못 함) | 대회 전엔 PWA 설치로 충분 |
| 서버가 구글 캘린더 API로 | 되지만 앱 검증 전엔 로그인이 7일마다 풀린다(구글 공식 문서) | 안 쓴다(지금 결정 그대로) |

- 폰 앱의 이점: 구글·애플·삼성 캘린더 주소를 사용자가 찾아 붙일 필요가 없다. 확인 팝업에서 저장한 일정을 폰 캘린더에 바로 써 넣을 수도 있다.
- **아직 확인 못 한 것**(실기기로 확인 — 2단계 할 일): 아이폰에 추가한 구글·아웃룩 계정 캘린더, 갤럭시의 삼성 캘린더가 다 읽히는지. 앱을 안 열었을 때 백그라운드로 읽히는지. 그전까지 밤 정리(01:30)는 '마지막으로 앱을 연 때'까지의 폰 캘린더로 한다.
- eTL은 폰 캘린더가 아니므로 앱이든 웹이든 서버가 ICS로 받는다.
- 출처: [Capacitor Calendar](https://capacitorjs.com/docs/apis/calendar) · [Expo Calendar(iOS 17 권한)](https://docs.expo.dev/versions/latest/sdk/calendar/) · [Google OAuth 7일 만료](https://developers.google.com/identity/protocols/oauth2) · [Apple Developer Program](https://developer.apple.com/programs/whats-included/)

## DB 표 ([schema.sql](../../schema.sql), 11-09 합의)

- `users`: id, google_sub, email, name, dept, year, created_at, etl_token(3단계, 암호화 저장 — 비밀번호는 절대 받지 않음). 로그인 세션은 표 없이 서명 쿠키
- `feeds`: 캘린더 주소 칸(etl·google·apple)마다 한 줄 — 잠근 주소, 지문, 마지막 시도·성공·실패, 연속 실패 수
- `events`: id, user_id, title, start, end, place, source(etl·google·apple·device·memo·timetable·kakao), ext_id, important
- `tasks`: id, user_id, title, due, minutes, ready(지금 가능 / 자료 뒤), done, source, ext_id, created_at
- `memos`: id, user_id, text, created_at, handled
- `briefings`: user_id, date, text(브리핑 카드 JSON)
- `log`: user_id, action, at — 측정용
- 3단계: `friends`, `groups`, `group_members`
- (user_id, source, ext_id)는 유일 → 같은 ICS를 다시 받아도 중복이 안 생긴다. 메모에서 나온 것은 ext_id `memo:<메모 id>`.
- 시각은 모두 `+09:00` 글자 한 모양(기본값도), 종일 일정 end는 끝난 다음 날.

## 피드백 고리 (이 계획의 핵심)

1. **다 같이 실제 일정으로 매일 쓴다.** 하루 한 번 이상 메모에 쓰고, 아침 브리핑을 본다.

3. **매일 밤 정한 10분**: 새 이슈를 훑고 담당을 붙인다. 버그 = 다음 날 안에, 불편 = 그 주 안에 묶어서, 추가 = 월요일 회의로.

6. **밤샘**: '밤샘' 라벨을 단 이슈는 밤에 AI 에이전트(Claude Code 등)에 맡기고 아침에 확인한다.
