# 부서별 세션 운영과 시작 프롬프트

갱신일: 2026-11-07. 이름 형식은 **프로젝트 이름 / 부서 / 세부 담당**입니다. `Project`는 임시 프로젝트 이름이며 저장소 `tt-wizard-gpt-edition`의 이름을 바꾸라는 요청이 아닙니다.

현재 대화는 **Project / Concept**입니다. 추가 6개 세션의 역할과 프롬프트를 준비했습니다. 이번 작업에서 사용자 소유의 새 채팅을 생성하거나 아래 기능을 구현한 것은 아닙니다. 예전 A~D 분담을 이 문서가 대체하며, 당시 프롬프트·기록은 이력으로 보존합니다.

**Research부터 시작**하고 Planner의 이수내역 정리를 병행합니다. Integrations·Legal의 공개 조사, Frontend의 검증 기준 준비, Document의 현황 정리는 지금도 할 수 있습니다. 실제 졸업요건 판정은 Research 자료를, 실제 GPT 연결은 Planner의 계산 결과를 받아 진행합니다.

지금은 별도 `Project / Backend` 총괄 세션이나 `Project / QA`를 추가하지 않습니다. 초기 통합 검증은 Frontend가 담당하며, 검증 규모가 커지면 `Project / QA`로 분리할 수 있습니다. 분리할 때 담당 파일과 인수인계를 먼저 갱신합니다. 하위 역할을 제안하는 것과 사용자 소유의 새 채팅을 실제로 만드는 것은 구분합니다.

## 공통 기준

- 실제 작업 위치: `D:\대학교\비교과\ChatGPT Edu 활용 상시 공모전\tt-wizard-gpt-edition`. 초기 `tt-wizard-gpt`와 저장소 밖 HTML 시제품을 현행 구현으로 혼동하지 않습니다.
- 읽기 순서: [AGENTS.md](../AGENTS.md) → [현재 상태](현재_상태.md) → [작업 목록](작업_목록.md) → 이 문서 → 자기 시작 프롬프트·관련 설계·코드.
- 실제 구현 상태를 파일·테스트로 확인합니다. 현재 구현은 작업 1 자료 준비까지이며, 프롬프트를 작성했다는 이유로 작업이 시작되거나 끝났다고 표시하지 않습니다.
- 받은 요청은 `prompts/<역할>-NN-제목.md`에 원문·결과로 기록합니다. 여기서 제공하는 시작 프롬프트는 제안본입니다. 실제 실행 기록은 해당 세션이 요청을 받은 뒤 남깁니다.
- 커밋·푸시는 사용자가 합니다. 기존 변경을 덮어쓰거나 다른 세션의 브랜치를 바꾸지 않습니다. 별도 작업 사본에서는 결과가 자동으로 공유되지 않으므로 선행 파일·버전을 확보한 뒤 통합합니다.
- 테스트 임시 경로는 `.test-tmp/research`, `.test-tmp/planner`, `.test-tmp/integrations`, `.test-tmp/frontend`, `.test-tmp/legal`, `.test-tmp/document`처럼 나눕니다. 다른 세션이 사용하는 임시 폴더 전체를 정리하지 않습니다.

## 담당 파일

아래 범위는 직접 수정할 곳입니다. 읽기는 기존 공개 범위와 AGENTS.md의 경로 제한을 따릅니다. 아직 없는 파일·폴더는 담당자가 필요한 때 만들며, 표에 적었다는 사실만으로 산출물이 존재하는 것은 아닙니다.

| 담당 | 직접 수정하는 범위 | 다른 담당에게 넘길 것 |
| --- | --- | --- |
| Concept | `AGENTS.md`, `docs/작업_목록.md`, 이 문서·시작 프롬프트, 서비스·자동화·계획서의 공통 설계, 스누지니 조사·목표 | 목적·범위·우선순위·담당 변경을 Document에 기록 요청 |

모든 세션은 자신의 `docs/sessions/<역할>.md`와 역할별 프롬프트 기록을 직접 작성합니다. 프롬프트 접두사·인수인계 이름은 `Concept`, `Research`, `Backend-Planner`, `Backend-Integrations`, `Frontend`, `Legal`, `Document`로 통일합니다. `prompts/01`의 원래 졸업요건 조사 원문은 실제 원문을 확보했을 때 Research가 기록합니다.

Planner의 계산 테스트 범위는 `test_transcript.py`, `test_requirements.py`, `test_courses.py`, `test_timetable.py`, `test_report.py`입니다. 기존 `scripts/sync_ttwizard.py`, 생성 강좌·이동 자료와 공통 설정은 이 분담으로 임의 수정하지 않습니다. 변경이 필요하면 Concept과 담당 범위를 조정하고, 관련 없는 자기 작업은 진행합니다.

Frontend라는 이름이 별도 웹사이트·서버를 새로 만들라는 뜻은 아닙니다. 현재 출품작의 기본 사용면은 GPT이며, 웹 화면이 필요하면 Concept이 범위와 담당을 먼저 정합니다. Frontend는 계산을 복제하지 않고 Planner 결과를 표시합니다. Planner는 Frontend가 작성한 설정을 묶음 생성 과정에서 덮어쓰지 않습니다.

## Concept과 Document의 경계

**Concept은 결정하고 Document는 근거를 확인해 기록합니다.** Document는 현황을 편집하면서 기능 범위·정책을 새로 정하거나 미검증 기능을 완료로 바꾸지 않습니다. Concept은 Document가 맡은 공통 기록을 동시에 편집하지 않습니다.

이번 부서 구성 전환에서는 Concept이 기존 안내·지침·현황과 요청 기록을 한 번 정리했습니다. 전환 이후 README·전체 현황·작업 기록·프롬프트 목록의 기본 담당은 Document입니다. 이는 종전의 ‘컨셉만 공통 문서를 통합’ 및 ‘모든 세션이 공통 문서를 직접 갱신’ 규칙을 대체합니다.

Document가 아직 작업하지 않았더라도 각 세션은 자기 인수인계 파일과 최종 답변을 남기면 됩니다. 다른 채팅이 자동으로 보고를 읽거나 알림을 받는다고 가정하지 않습니다. 사용자는 Document에 ‘각 세션 인수인계를 반영해 줘’, Concept에 ‘현재 상태를 보고 다음 우선순위를 정해 줘’라고 요청할 수 있습니다. 전체 기록의 마지막 통합 시점도 표시합니다.

## 인수인계와 검증

모든 인수인계에는 아래 항목을 넣습니다.

- 역할·확인일·기준 커밋·관련 스누지니 G번호·실제 요청 기록 경로.
- 바뀐 파일, 구현·검증된 동작, 설계만 한 내용, 아직 없는 것.
- 입력·출력 형식, 실행 방법·검증 명령·결과·확인하지 못한 범위.
- 다른 담당에게 필요한 변경, 공통 문서 반영 요청.
- 다음 한 과제의 입력·산출물·완료 기준, 필요한 외부 확인, 커밋·푸시 여부와 제안 메시지.

구체적인 연결 기준은 다음과 같습니다.

1. **Research → Planner:** 2025학번 7묶음 JSON·스키마·공식 근거·적용 연도·확인 필요. 형식 검증과 규정 사실 확인을 구분합니다. 원문 사실을 임의로 덮어쓰지 않습니다.
2. **Planner → Integrations·Frontend:** 개인정보 없는 이수내역·판정·추천 형식. 원래 명세에 빠진 취득 완료·수강 중·미확인 상태를 표현하는 형식을 먼저 문서화합니다. 상태가 없으면 취득 완료로 추정하지 않습니다. Research 산출물 전 임시 예시는 실제 규정이 아닙니다.
3. **Integrations ↔ Legal:** 전자는 기술적 조회 가능성, 후자는 이용 조건의 근거를 확인합니다. HTTP 응답이나 로그인 성공을 전체 이수내역 조회·허가로 해석하지 않습니다. Legal 검토도 학교의 실제 회신·허락을 대신하지 않습니다.
4. **Frontend → 개발 담당:** 입력·근거 있는 기대 결과·실제 결과·재현 방법. 기대 결과는 공식 규정과 수작업 계산으로 독립적으로 만들고 구현 출력을 정답으로 복사하지 않습니다.
5. **모두 → Document → Concept:** 개별 보고와 파일을 대조해 전체 현황을 갱신하고, Concept이 그 근거로 다음 우선순위를 결정합니다. 모든 담당의 주장을 무조건 검증 완료로 취급하지 않습니다.

실제 성적표·계정·비공개 화면은 공개 저장소에 넣지 않습니다. 마이스누 화면 자동 읽기는 정보화본부 회신 조건이 남아 있으므로 Integrations의 초기 작업은 공식 공개 경로 조사와 모의 연결입니다. 실제 정기 조회·메시지 발송·GPT Actions·공개 배포는 시작 프롬프트만으로 실행하지 않습니다. Legal은 문의 초안까지 만들 수 있지만 외부 발송이나 허락 취득을 대신 수행하지 않습니다. 공개 조사·가상 자료 계산·문서 정리는 이러한 실제 연결 조건과 별도로 진행합니다.

## 기존 역할에서 옮기는 위치

| 이전 역할 | 현재 담당 |
| --- | --- |
| A 자료·졸업요건 | Research |
| B 계산·시간표 | Backend / Planner |
| C 학교 연동·알림 | Backend / Integrations, 이용 조건 검토는 Legal |
| D GPT·시연·검증 | GPT 사용면·통합 검증은 Frontend, 계산 묶음은 Planner, 제출 설명은 Document |
| 컨셉의 공통 기록 통합 | 결정은 Concept 유지, 현황·README·기록 편집은 Document |

과거 A~D 문서가 실제로 생겼다면 새 담당이 읽고 이관 경로를 남깁니다. 다른 세션의 변경을 삭제하거나 이름만 바꿔 완료 처리하지 않습니다.
