## 구현과 경계

`CourseKey(semester, code, section)`은 번호를 문자열로 유지한다. `MockSyllabusTracker`는 최근 조회 결과와 마지막 정상 상태·시각을 나눠 보존한다. 첫 관측부터 등록이면 알림이 없고, 실패/미확인 뒤 첫 등록과 확인된 미등록 뒤 등록은 서로 다른 사건이다. 개별 끄기와 최초 등록 이력은 선택 목록 갱신·재추가·JSON 복원 후에도 유지한다. `MockSink`는 가상 사건 식별자로 중복 기록을 막고 수신 전 실패·수신 후 응답 유실을 재현한다.

학사 연결은 [Planner 입력 v1](../../planner/transcript_format.md)의 `normalize_transcript`를 호출한다. 로그인 상태만으로 `coverage=complete`를 만들지 않는다. `MockAcademicSession`은 최근 조회와 마지막 성공 자료·확인 시각을 따로 보관한다. 마지막 성공에는 부분 조회도 포함되며 이전 전체와 합치지 않는다. 정상 빈 결과, 부분 결과, 실패/만료를 구분하고 코어 학점·요건 계산을 복제하지 않는다. 모든 예시는 가상이며 접두사·mock 표시는 개인정보 탐지 기능이 아니다.

현재 한계:

- 실제 API·SSO·마이스누 화면 자동 읽기·계획서 크롤러·예약 작업·GPT Actions·외부 메시지 없음.
- 영속 저장소·다중 작업자·실제 전달 서비스의 중복 방지 보장은 없음. 모의 Tracker와 Sink snapshot을 함께 보존하는 흐름만 검증한다.
- 선택한 시간표와 별도 관심 목록의 합집합은 호출자가 만든다. 이 코드는 추천 후보만으로 목록을 교체하지 않는다.
- 과목명과 공식 원문 찾기 안내는 Frontend가 같은 학기·번호·분반으로 결합해야 한다. 검증되지 않은 과목별 URL을 조합하지 않는다.
- 원문 수정·삭제 후 재등록 알림, 전공 진입 연도 등 Planner v1 밖의 필드, 실제 학교 데이터의 완전성은 미구현/확인 필요다.
- 모의 연결 완성으로 G01·G21의 실제 학교 연동 완료를 선언할 수 없다.
