# 강의계획서를 모아 보고, 등록되면 알림 받기

**관심 과목의 강의계획서를 한곳에서 확인하고, 아직 없는 계획서가 등록되면 알림을 받습니다.** 과목마다 업로드 시점이 달라 일일이 다시 접속해야 하는 불편을 줄이는 것이 목적입니다.

- 정리일: 2026-11-06
- 현재 상태: 추가 요구사항과 판단 기준 정리 완료. 실제 조회·정기 확인·알림 발송은 미구현.
- 사용자 요청: [프롬프트 원문](../prompts/00e-강의계획서-알림.md)

## 학생이 사용하는 순서

1. 시간표를 선택하면 그 과목들의 계획서 목록을 자동 구성합니다. 비교할 다른 관심 과목도 추가할 수 있습니다.
2. **과목명·분반 / 계획서 등록 상태 / 마지막 확인 시각 / 원문 보기**를 한 목록에서 봅니다.
3. ‘이 시간표의 계획서 알림 받기’를 한 번 켜면 대상 과목을 한꺼번에 등록합니다. 과목별로 켜거나 끄는 것도 가능하게 합니다. 알림 대상은 학기·교과목번호·강좌번호로 구분합니다.
4. 정해진 주기로 등록 여부를 확인하고, 새로 등록된 것이 확인되면 한 번 알립니다.
5. 알림에서 원문을 확인하고 수강할지 결정합니다. 관심 과목 삭제와 알림 끄기도 제공합니다.

모아보기의 첫 범위는 등록 상태와 공식 원문 접근 경로를 한곳에 모으는 것입니다. 원문을 화면 안에서 함께 읽는 기능은 문서 조회·이용 방식이 확인되면 검토합니다. 계획서 미등록 자체를 과목 추천 제외 사유로 쓰지 않습니다.

로그인부터 추천까지 이어지는 [자동화 흐름](자동화_흐름.md)에 연결합니다. 계획서 등록 여부는 시스템이 주기적으로 확인하며 학생에게 반복 조회를 요구하지 않습니다. 선택한 시간표 전체에 알림을 켠 경우 이후 그 시간표에서 추가·삭제한 과목도 확인 대상에 반영하고, 바뀐 목록을 보여 줍니다. 별도로 관심 등록한 과목은 유지합니다. 새로 추천된 후보가 생겼다는 이유만으로 선택한 시간표나 알림 대상을 바꾸지는 않습니다.

시간표 전체 알림을 켠 뒤 특정 과목만 끈 경우에는 그 과목의 끄기 설정을 우선합니다. 같은 학기·과목·분반의 목록 갱신이나 시간표 재계산으로 알림을 다시 켜지 않습니다. 학생이 직접 다시 켤 때만 변경합니다.

## 화면에서 구분할 상태

| 표시 | 언제 이렇게 표시하나요? |
| --- | --- |
| 등록 확인 | 해당 학기·과목·분반의 계획서 원문이나 공식 등록 표시를 확인했습니다. |
| 미등록 확인 | 정상적으로 조회했고, 공식 자료에서 미등록임을 명시적으로 확인했습니다. |
| 아직 확인하지 않음 | 최초 조회 전이거나 등록 여부를 판단할 근거가 없습니다. |
| 조회 실패 | 접속 오류·로그인 필요 등으로 이번 확인을 마치지 못했습니다. |

빈 화면, 찾을 수 없는 주소, 접속 실패를 ‘미등록 확인’으로 바꾸지 않습니다. 마지막 조회 결과와 마지막으로 확인한 등록 상태를 따로 보관합니다. 예를 들어 이전에 등록을 확인한 뒤 오류가 나면 **‘최근 조회 실패 · 이전 등록 확인 시각 …’**으로 보여 줍니다. 알림 이력도 유지합니다.

**확인 시각은 실제 업로드 시각과 다릅니다.** 공식 자료가 업로드 시각을 제공할 때만 따로 표시합니다. 확인 주기 사이에 올라온 문서는 다음 확인 때 발견되므로 실시간 알림으로 소개하지 않습니다.

## 알림을 보내는 기준

| 상황 | 처리 |
| --- | --- |
| 관심 목록에 담고 처음 조회했을 때 바로 등록을 확인함 | 목록에 ‘등록 확인’으로 표시합니다. 새 업로드 알림은 보내지 않습니다. |
| 미등록을 확인한 뒤 등록을 확인함 | 알림을 켠 과목에 ‘강의계획서 등록을 확인했습니다’라고 한 번 알립니다. |
| 첫 조회가 실패하거나 판정 불가였고, 알림을 켠 상태에서 이후 조회로 처음 등록을 확인함 | ‘처음 등록을 확인했습니다’라고 한 번 알립니다. 새로 업로드된 시점은 알 수 없다고 구분합니다. |
| 등록된 상태로 다시 확인됨 | 같은 등록 알림을 반복하지 않습니다. |
| 조회 실패 후 등록된 상태로 복구됨 | 기존 상태와 알림 이력을 이어 씁니다. 이미 보낸 등록 알림을 다시 보내지 않습니다. |
| 등록된 계획서의 내용이 수정됨 | 최초 등록과 다른 사건입니다. 수정 감지·수정 알림은 별도 확장 항목으로 남깁니다. |

알림에는 **학기, 과목명, 교과목번호·강좌번호, 확인 시각, 공식 원문을 보는 경로**를 넣습니다. 전달 실패로 다시 시도하더라도 같은 등록 사건의 알림을 중복 발송하지 않도록 구현합니다. 다음 학기는 별도 대상으로 취급하고 이전 학기의 알림 이력을 섞지 않습니다. 알림 대상 학기가 끝나거나 학생이 끄면 확인을 중단할 수 있어야 합니다.

예시 문구(지어낸 자료이며 실제 발송 결과가 아님):

> 예시 과목 A · 001분반의 강의계획서 등록을 확인했습니다. 확인 시각: 2026-11-06 09:00. 공식 원문에서 수업 내용을 확인하세요.

## 구현에 필요한 것과 현재 확인한 범위

필요한 구성은 **관심 과목 목록 → 공식 자료 조회 → 이전 상태와 비교 → 알림 전달 → 목록 갱신**입니다. 정기 확인을 실행할 곳과 알림을 보낼 수단이 필요합니다.

현재 [강좌 자료 형식](../data/README.md)과 [자료 생성 코드](../scripts/sync_ttwizard.py)에는 강의계획서 주소·등록 여부·업로드 시각이 없습니다. 이 자료만으로는 미등록이나 새 등록을 판정할 수 없습니다. 기존 분반의 ‘폐강대상’ 상태도 계획서 등록 여부를 뜻하지 않습니다.

기존 TT Wizard의 [수강편람 링크 구현 메모](https://github.com/Archi142857/tt-wizard/blob/7b5795b9f230972de53d80379f84c42d7e4ceabc/docs/timetables.md)는 강의계획서 주소를 직접 열면 첫 화면으로 돌아가는 동작을 기록하고 있습니다. 이는 기존 구현에서 남긴 기록이며, 이번 작업에서 공식 사이트의 현재 동작을 검증한 결과는 아닙니다. 과목별 주소를 임의로 조합하지 않고, 실제로 열리는 원문 링크가 확인되면 사용합니다. 직접 열 수 없다면 [서울대학교 수강신청 사이트](https://sugang.snu.ac.kr/)와 학기·교과목번호·강좌번호로 찾아가는 안내를 제공합니다.

| 확인 필요 | 확인할 곳·정할 내용 |
| --- | --- |
| 공식 조회 경로와 판별 근거 | 수강편람 담당 부서·정보화본부에 사용할 수 있는 조회 방법, 등록/미등록 구분, 로그인 필요 여부를 확인합니다. |
| 정기 확인 방식 | 허용되는 조회 빈도와 실행할 환경을 확인합니다. 학교 답변 전에는 마이스누 자동 조회를 구현하지 않습니다. |
| 알림 수단 | 앱 내 알림·이메일 등 어디로 전달할지 정합니다. 이 요청만으로 개인 알림이나 이메일 발송을 설정하지 않았습니다. |
| 알림 설정 보관 | 관심 과목과 알림 설정을 저장할 위치, 학생이 끄거나 삭제하는 방법을 정합니다. 공개 저장소에는 구독자 정보나 연락처를 넣지 않습니다. |
| 원문 모아보기 범위 | 링크 제공, 화면 내 열람, 원문 저장 중 가능한 방식을 확인합니다. 계획서 원문을 공개 저장소에 일괄 복제하지 않습니다. |

적용 지침은 [AGENTS.md](../AGENTS.md)의 ‘꼭 지킬 것’ 1·4·5·8·9번입니다. 교수 정보와 실제 학생 자료는 공개 파일·출력·GPT 지식에 넣지 않습니다. GPT Actions 도입은 별도 결정 사항이며, 이 기능을 위해 미리 켜지 않습니다.

## 구현 후 확인할 것

- 같은 이름의 과목이라도 학기·교과목번호·분반이 다르면 따로 처리되는지.
- 최초 확인에서 이미 등록된 문서를 새 업로드로 알리지 않는지.
- 정상적으로 미등록을 확인한 뒤 등록되면 알림이 한 번 오는지.
- 처음에는 조회하지 못했던 과목이 등록 상태로 확인되면 최초 발견으로 구분하는지.
- 반복 확인·접속 오류·재시도·실행 재개 후에도 중복 알림이 없는지.
- 조회 실패가 미등록으로 표시되거나 기존 확인 기록을 지우지 않는지.
- 알림 끄기·관심 과목 삭제·대상 학기 변경이 반영되는지.
- 원문 접근 경로가 실제로 열리고 과목을 찾는 데 필요한 번호가 맞는지.

먼저 지어낸 자료로 상태 변화와 알림 판단을 확인합니다. 실제 정기 조회가 연결되기 전 공모전 화면에는 ‘모의 시연’이라고 표시합니다. 효과는 반복 확인에 쓰던 시간과 실제 알림 도착 시간을 측정한 뒤 기록합니다.
