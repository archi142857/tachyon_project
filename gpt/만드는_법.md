# GPT 설정 준비와 오프라인 확인

2026-11-07. **미적용 초안입니다. 실제 GPT 생성·파일 업로드·공유·이전은 수행하지 않았습니다.** 계산 묶음의 로컬 실행과 ChatGPT에서의 실행은 별도 검증입니다. 학교 Edu 계정 상태를 확인하기 전에는 아래 설정안을 실제로 적용하지 않습니다.

## 1. 계정에서 먼저 확인할 것

OpenAI 공식 안내의 일반 GPT 종료 예정일은 2026-12-11이며 일부 승인된 예외는 일정이 다릅니다. 전환 대상은 모든 플랜이지만 생성·이전 권한과 제공 시점은 계정·작업공간마다 다릅니다. 일부 Enterprise의 신규 생성은 2026-10-26에 끝났습니다. 서울대 Edu의 적용 일정·기존 GPT 여부·생성/편집/공유 권한은 **미확인**입니다. 개인 계정의 신규 GPT 생성·공개도 현재 제공되지 않는다고 안내돼 있습니다. 버튼이 있다고 가정하지 말고 실제 학교 작업공간 공지를 확인해야 합니다. [종료·이전 FAQ](https://help.openai.com/en/articles/20001519-custom-gpt-retirement-and-migration-faq), [GPT 생성·편집 안내](https://help.openai.com/en/articles/8554397-creating-and-editing-gpts)

계정 확인 결과에는 확인일, 개인/학교 작업공간 구분, 기존 GPT 유무, 허용된 생성/편집/실행/공유, 적용 종료일을 적습니다. 계정 식별자·개인 화면·관리 주소는 공개 저장소에 남기지 않습니다. 기능이 없으면 ‘설정 적용 불가/확인 필요’로 기록하고, Concept이 제출 방식과 후속 경로를 결정합니다. 임의로 사이트나 플러그인으로 전환하지 않습니다. [Legal 검토 L06·L07·L11](../docs/legal/검토_현황.md)도 함께 확인합니다.

## 3. 로컬 묶음 생성과 실행 계약

계산 코드와 생성기는 Planner 담당입니다. [묶음 계약](../planner/bundle_format.md)을 기준으로 사용하며 Frontend가 계산 코드를 다시 만들지 않습니다. 프로젝트 루트에서 생성하는 명령은 다음과 같습니다.

```powershell
python scripts/build_gpt.py --target-term 2027-1 --output-dir gpt/knowledge
```

묶음의 목표학기는 생성 시 고정됩니다. 실제 목표학기 편람이 없으면 정확히 전년 같은 학기만 예상 자료로 쓰며, 두 학기 모두 없으면 자료 부재입니다. 전체 제공 편람은 과거 이수 매칭과 5년 개설 이력을 위해 보존됩니다. 생성된 manifest의 실제 목표/자료 학기와 누락 연도를 확인합니다. 위 명령만으로 생성 성공을 뜻하지 않습니다.

생성된 세 파일을 저장소 밖 새 폴더에 복사한 뒤 실행합니다. 입력·결과는 완전히 지어낸 자료만 사용합니다. 개인 자료를 저장소나 재현 폴더에 넣지 않습니다.

```powershell
python -I -S planner_bundle.py --verify
python -I -S planner_bundle.py --transcript example.json --preferences preferences.json --format json
```

`--transcript -`는 표준입력 JSON을 받습니다. `--format markdown`은 같은 계산의 보고 본문입니다. `run()`은 `transcript`, `requirements`, `candidates`, `json`, `markdown`을 반환합니다. 다른 목표학기를 전달하면 오류이며 새 목표용 묶음을 만들어야 합니다. 입력·자료 검증 실패는 종료 코드 2와 고정 오류로 표시합니다.

실제 코드 실행 환경에서 위치를 확인한 후에는 다음 호출 형태를 씁니다. `bundle_path`, `payload`, `preferences`는 각각 실제 확인한 파일 경로·가상 입력·학생이 정한 조건입니다. 이 예제는 파일 존재나 세션 성공을 가정하는 실행 기록이 아닙니다.

```python
import importlib.util

spec = importlib.util.spec_from_file_location("tt_planner_bundle", bundle_path)
bundle = importlib.util.module_from_spec(spec)
spec.loader.exec_module(bundle)
manifest = bundle.verify_bundle()
result = bundle.run(payload, preferences=preferences,
                    target_term=manifest["target_term"])
```

묶음은 표준 라이브러리와 내장 자료를 사용합니다. 설치·인터넷·학교 로그인이 필요 없는 계약입니다. 임시 자료를 정리하는 로컬 코드 동작을 ChatGPT 서비스의 대화·파일 미보관 보장으로 확대하지 않습니다. [개인정보·자료 조건 검토](../docs/legal/검토_현황.md)의 미확인 사항을 유지합니다.

## 4. 학생 흐름과 성공 기준

1. [가상 3사례](../demo/가상_입력.md)를 표 또는 구조화 입력으로 준비합니다. 실제 PDF·표 인식은 별도 미검증 항목입니다.
2. 읽은 과목 표·취득 상태·일부/전체 여부를 확인받습니다. 상태 누락·반복·학점 불일치를 추측으로 고치지 않습니다.
3. 묶음을 검증·실행하고 자동 5목록 범위와 수동 85항목을 구분합니다. 학생에게 적용되는 항목의 근거와 확인 이유를 보여 주며 전체 졸업은 미판정으로 둡니다.
4. 목표학기·학점·회피 시간·출발 건물·추가/필수 과목·참고 후보 여부를 한 번에 확인합니다. 기본값을 썼다면 밝힙니다.
5. 실제 반환된 최대 3안만 비교합니다. 걷기·부족분·미정 구간·예상 자료·선수/다전공 확인·출처를 유지합니다. 0~2안 또는 탐색 한도도 그대로 표시합니다.
6. 입력을 수정하면 다시 계산하고 [3사례 독립 기대값](../demo/독립_기대값.md)과 [묶음 독립 기대값](../demo/묶음_독립_기대값.md)을 대조합니다. [합성 시간표 경계](../demo/시간표_독립_기대값.md)는 원래 모듈에 편람·이동표를 주입한 검사 근거이며, 묶음 run()에서 그대로 재현하는 사례가 아닙니다. 계정에서 검증할 때에는 로컬 출력과 실제 GPT의 숫자·문구·자료 학기를 따로 비교합니다.

별도 폴더 실행 결과는 [검증 결과](../docs/검증_결과.md)와 [Frontend 인수인계](../docs/sessions/Frontend.md)에 실행 시점·파일 해시·성공/실패로 기록합니다. 결과가 없는 기능은 준비/미검증으로 남깁니다. 실계정에서 파일 읽기, 확인 질문, 코드 실행, 결과 표시가 각각 관찰되기 전에는 GPT 통합 시연 성공으로 표시하지 않습니다.

## 5. 이전·공유는 별도 후속 작업

공식 문서상 이전은 사용 가능한 계정에서 수행하며 게시된 최신 버전을 기준으로 합니다. 초안·미게시 수정은 이전되지 않고 원 GPT는 이전 후 읽기 전용이 됩니다. 대체 기능은 기존 예시와 어려운 경계 사례로 재검증해야 합니다. 현재 이 프로젝트는 이전·게시·공유를 실행하지 않았고, 학교 구성원 접근이나 공모전 제출 형식도 확인하지 않았습니다. [이전 FAQ](https://help.openai.com/en/articles/20001519-custom-gpt-retirement-and-migration-faq)

학생이 만든 비공식 도구예요. 졸업 사정은 학과와 마이스누에서 최종 확인하세요. 다른 사람의 성적표는 올리지 마세요.
