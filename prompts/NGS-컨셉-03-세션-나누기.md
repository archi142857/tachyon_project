# NGS · 컨셉 03 · 세션 나누기와 세션끼리 소통하는 방식

- 날짜: 2026-11-09
- 도구: Claude (claude.ai 프로젝트 세션, Claude Opus 5.5)
- 기록 유형: 사용자 직접 지시
- 목적: 백엔드부터 시작하면서, 여러 AI 세션이 나눠 일하고 서로 쪽지로 소통하는 방식을 만든다.

## 프롬프트 원문

사용자가 다른 프로젝트에 썼던 지시를 참고용으로 붙였다. 개인 PC 경로, 실명, 개인 이메일은 가렸다. 나머지는 원문 그대로다.

````text
일단 백엔드부터 시작하자. 다른 AI랑 실시간으로 소통하면서 작업하는 시스템 만들고, 앞으로 내가 멈추라고 하기 전까지는 계속 할 수 있는 작업을 해.

Grid Game 을 Ultimate RSP 처럼 여러 세션으로 나눠 굴리고 싶어. 너는 앞으로 이 프로젝트의 '컨셉' 세션(사이드바 이름 Grid / Concept)이 돼서 세션 나누기와 공통 규칙을 맡아. 지금 세션은 너 하나야.
먼저 할 일
1. 지금까지의 작업(레포, PC 폴더, 화면, 남은 일)을 프로젝트 문서 `Grid_Game_작업_방식.md` 에 정리해. 비슷한 문서가 이미 있으면 그걸 고쳐. 이 문서는 모든 세션이 처음에 읽는다.
2. PC 폴더 (생략: 개인 PC 경로) 접근을 요청해. (생략: 개인 PC 경로) 의 다른 폴더는 건드리지 않는다.
3. 그 폴더 안에 `세션소통\` 을 만든다: `README.md`(아래 규칙), `받은편지함\<세션>\`(세션마다 폴더 하나), `자료\`(그림·문서).
4. Grid Game 에 맞는 세션 나누기를 짧게 제안해 줘(예: 컨셉·디자인·프론트엔드·백엔드·검수·문구 가운데 필요한 것만). 세션마다 맡는 레포 경로가 겹치지 않게 나눈다. 내가 고르면 정한다.
5. 정해지면 세션마다 첫 메시지로 붙여 넣을 초기 프롬프트를 하나씩 써 줘.
세션소통 규칙(README 에 적을 것)
- 세션은 서로를 못 깨운다. 사용자가 "쪽지 확인해"나 "공유 폴더"라고 하면 그때 자기 받은편지함을 본다.
- 쪽지 하나 = 파일 하나. 받는 세션 폴더 `받은편지함\<세션>\` 에 `YYMMDD-HHMM_<보낸 세션>_<짧은-제목>.md` 로 만든다. 첫 줄은 `# 제목`, 본문은 짧게 반말. 만든 뒤엔 고치지 않고, 더할 말은 새 쪽지로. 답장은 제목 앞에 `답-`.
- 받는 쪽은 폴더 목록에서 `_처리.md` 에 없는 파일을 새 쪽지로 읽고, 처리하면 자기 `_처리.md` 에 `- <파일 이름> · 끝 (한 일)` 한 줄을 적는다. `_` 로 시작하는 파일은 쪽지가 아니다. `_처리.md` 는 받는 세션만 쓴다.
- 다른 세션에 쪽지를 남긴 답은 맨 끝에 `공유폴더: 프론트엔드, 디자인` 처럼 한 줄을 쓴다. 세션 이름은 한국어로 짧게, 'Grid /' 는 안 붙인다.
- PC 에 파일을 올릴 때는 SendUserFile 로 받은 file_uuid 를 device_commit_files 에 넣고, 올린 뒤 다시 받아 크기·내용을 확인한다(stagedPath 로 예전에 올린 이름을 다시 올리면 예전 내용이 써진 적이 있다). 이미 있는 파일은 쓰기 직전에 다시 받아 그 위에서 고치고 expectedMtimeMs 를 넣는다. force 는 안 쓴다.
- 그림·문서는 `자료\` 에 두고 쪽지에는 경로만 적는다.
- 레포 파일은 맡은 경로만 고친다. 남의 경로는 그 세션에 쪽지로 부탁한다.
- 디자인은 시안 3개를 그림으로 짧게 먼저 보여 주고, 내가 고른 것만 완성한다.
레포에 올리기(모든 세션 같음)
- add_repo(owner, repo, access push)로 붙이고 샌드박스에서 고친 뒤 main 에 바로 푸시한다. 처음 한 번은 내 허락이 필요할 수 있다.
- 커밋 작성자는 내 이름으로: git config author.name "(생략: 실명)", author.email 은 내가 예전에 한 커밋과 같게. 커미터는 그대로 둔다.
- 커밋 메시지: 첫 줄 `한글 요약 / English imperative summary`, 빈 줄, 한글 글머리표, 빈 줄, 같은 내용 영어 글머리표, 맨 끝에 Co-Authored-By 줄.
- 푸시 바로 전에 git fetch 하고, 밀렸으면 rebase. 테스트가 있으면 돌리고 올린다. 올린 뒤 나한테는 GitHub Desktop 에서 Pull origin 만 부탁한다.
같이 지킬 것
- (생략: 다른 프로젝트의 제작자 표기와 개인 이메일)
- 토큰·키 같은 비밀 값은 채팅·파일·레포에 적지 않고 GitHub Secrets 에만 둔다.
- 나한테는 한국어 반말로 짧게.

위에는 내가 다른 프로젝트한테 명령할 때 썼던 건데, 세션 나누는 것만 참고해서 나한테 결과 줘봐. 내가 세션 만들어줄게
````

## 결과 요약

archi142857 노트북의 세션 4개(컨셉·서버·AI·화면)를 맡는 경로가 겹치지 않게 나누고, 세션마다 첫 메시지로 붙여 넣을 프롬프트를 사용자에게 줬다. 공통 규칙은 claude.ai 프로젝트 문서 `Tachyon_작업_방식.md`와 레포 사본 [세션 운영](../docs/ngs/세션_운영.md)에 적었다. 그사이 팀원이 [소통판](../docs/ngs/소통.md)·Cloudflare 뼈대·`schema.sql` 초안을 먼저 올려서, 우리 쪽 규칙을 팀 규칙(소통판, 계획의 '작업 중' 표시, 각자 푸시) 아래에 맞췄다. 따로 만든 `schema.sql` 초안은 올리지 않고 팀원 초안에 소통판으로 의견을 달았다.
