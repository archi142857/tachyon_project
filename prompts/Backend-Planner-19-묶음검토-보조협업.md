# 작업 4: 묶음 검토 보조 협업 원문

- 날짜: 2026-11-07.
- 분류: AI 보조 에이전트 협업. 사용자 직접 지시가 아니다.
- 도구: Codex 보조 에이전트 협업.
- 송수신 담당: Project / Backend / Planner 본 담당 ↔ 묶음 읽기 검토 보조.
- 목적: 오프라인 묶음의 의존파일·입력 검증·재현성·개인정보 경계를 기존 구현과 대조한다.
- 수정 범위: 이 원문 기록 파일만 작성했다. 구현 코드·자료·공통 문서는 수정하지 않았다.
- 결과: 첫 검토에서는 계약과 기존 모듈을 읽고 보존할 경계와 구현 주의점을 전달했다. 그 시점에는 `scripts/build_gpt.py`가 없었다. 이후 본 담당의 생성 알림을 받고 빌더·실행기·검증 파일을 추가로 읽어 출처 명세의 임의 필드 포함과 생성/실행 용량 한도 불일치를 보고했다. 본 담당이 수정한 코드에서 두 경계가 보완됐음을 읽기 재검토로 확인했다. 실제 실행 재현·전체 테스트 통과 여부는 이 읽기 검토의 결과가 아니다.
- 검토 대상: [묶음 계약](../planner/bundle_format.md), [규정 계산](../planner/requirements.py), [이수내역 정리](../planner/transcript.py), [규정 검증](../scripts/validate_requirements.py), [자료 설명](../data/README.md), [규정 자료 설명](../data/requirements/README.md), [자료 생성 코드](../scripts/sync_ttwizard.py), [묶음 생성 코드](../scripts/build_gpt.py), [실행기](../planner/bundle_runtime.py), [묶음 검증](../tests/test_build_gpt.py).
- 공개 가림: 아래 발화 원문에는 개인 절대경로·내부 에이전트 식별자가 없다. 전달 도구의 내부 메타데이터는 넣지 않았으며 송수신은 담당명으로 표시했다. 원문의 문장·띄어쓰기·오탈자를 고치지 않았다.
- 검증 범위: 읽기 검토이며 코드를 실행하거나 실제 GPT·학교 연결을 확인한 결과가 아니다.

## 1. 본 담당 → 검토 보조: 작업 배정

## 8. 검토 보조 → 본 담당: 빌더·실행기 검토 결과

```text
생성된 build_gpt.py와 bundle_runtime.py 읽기검토에서 명확한 보완점 2개입니다. (1) _validate_data는 data/source_manifest.json의 basis_year 타입만 검사한 뒤 원본 전체를 ZIP에 넣습니다. 예를 들어 최상위 private_note 또는 inputs['개인 절대경로']를 추가해도 통과하므로 메타 개인정보 비포함 경계가 뚫립니다. 동기화 산출물의 고정 키·상대경로/해시·집계 형식만 허용해 주세요. (2) 빌더는 파일별 32MiB만 검사하지만 실행기는 ZIP/총멤버128MiB·멤버1024·manifest4MiB 제한도 둡니다. 여러 개의 적법한 개별파일 합계가 한도를 넘으면 생성은 성공하고 기존3파일을 교체한 뒤 --verify는 실패합니다. 쓰기 전 런타임과 같은 총한도·구성검증을 추가해야 합니다. 실제 실행 재현은 하지 않은 코드 경로 검토 결과입니다. source local 표현 수정은 이미 반영된 것으로 보입니다.
```
