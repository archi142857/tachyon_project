# Tachyon-30 · 메모 시각: 시 없는 범위('7-9') · 그 일을 보통 하는 때로 오전·오후와 추천

- 날짜: 2026-11-15
- 도구: Claude Code (Claude 데스크톱 앱 Code 탭, Claude Opus 5.5) — node --test(서버 시험), vitest · vite build. 실제 AI(Haiku) 답은 이 노트북에서 못 돌려(API 키는 Cloudflare 비밀값) 바꾼 프롬프트는 배포 뒤 확인
- 기록 유형: 사용자 직접 지시
- 목적: '7-9 합주'를 07:00~08:00 아침으로 추천하던 것을 고친다. 시 없이 쓴 시각도 읽고, 오전·오후와 시각 추천은 그 일을 보통 하는 때를 보고 고른다.

## 프롬프트 원문

11-15 15:40 (메모 팝업 캡처 '이대로 저장할까요? … 11월 24일 (화) 07:00 ~ 08:00 추천'과 함께)

````text
여전히 말을 잘 못알아들어. 7-9 합주라고 했는데 추천에 7-8을 띄워주고, 심지어 아침이야. 시간을 저렇게 적어도 알아듣게 해주고, 오전/오후에 할만한 일들을 잘 보고 시간 추천을 좀 더 잘 해줘
````

## 한 일

- 원인: 정규식이 '3~5시'처럼 '시'가 붙은 범위만 읽어서 '7-9'를 시각으로 못 봄 → AI가 '7'만 07:00으로 주고, 끝은 기본 1시간(08:00)이라 '추천' 점선.
- 정규식(`worker/3_memo_popup.js` `HOUR_RANGE`): '7-9' · '7~9' · '14-16' · '11-1'도 시각 범위. 뒤에 단위 말('3-1반' · '2-3명' · '1-2주' · '10-15분')이 오거나 6시간을 넘으면('11-24') 시각이 아님. 오전·오후를 안 쓴 7-9는 규칙으로 19:00~21:00.
- AI 프롬프트(`worker/prompts/memo_popup.js`): 범위는 시작 시각, 오전·오후는 그 일을 보통 하는 때로(합주·공연·회식·술자리·동아리 모임 = 저녁, 수업·회의·면담·스터디 = 낮, 7·8시를 아침으로 읽는 건 아침에 하는 일만). 예시에 '토요일 밴드 합주 7-9 → 19:00'.
- 시각을 안 쓴 일정: AI가 새 칸 `part`(아침·오전·점심·오후·저녁·밤·?)로 그 일을 보통 하는 때를 고르면, 그 시간대에서 내 일정과 안 겹치는 빈 시간을 추천(`lib/known.js` `suggestFree`). 메모에 쓴 시간대 말이 먼저, 여행 같은 종일 일은 '?'로 비워 둠. 팝업 안내: '보통 저녁에 하는 일이라 저녁의 비어 있는 시간으로 골랐어요'.
- 시험: 서버 35개 통과(시 없는 범위 5개, 시각이 아닌 범위 7개, AI가 9-11 합주를 저녁으로 옮김, part 추천·쓴 시간대 우선·종일). 화면 194개 · 빌드 통과.
- 남은 것: 실제 Haiku가 새 규칙대로 답하는지는 배포 뒤 메모 몇 개로 확인.
