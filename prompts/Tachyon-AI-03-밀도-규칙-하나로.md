## 결과 요약

- 쪽지 `261111-2228_컨셉_밀도-고르게-규칙-맞추기.md`: 컨셉이 화면에서 하다 만 셈(패치 안 `web/src/density.js`: 7~24시, 가장 덜 찬 날부터 15분씩, 정오 전 마감은 전날까지)과 `4_night.js`의 서랍장(하루 3시간 칸, 18시 기준)을 견줘 **서버 한 곳(`planDays`)으로** 정했다. 화면 셈의 물 채우기를 그대로 가져오고, 하루 편한 몫(3시간)을 먼저 채운 뒤 모자라면 빈 시간까지(빠듯), 그래도 남으면 넘침으로 나눴다. 여유(`slack_days`)도 같은 편한 몫으로 세서 '여유 < 0 ⟺ 빠듯·넘침 ⟺ 모자라요 경고'가 맞는다.
- 새 주소 `GET /api/briefing/plan?days=42`(오늘부터 날마다 일정·할 일·빠듯·넘침·몰아서 할 때·할 일별 분). `web/API.md`에 모양과 그리는 법 제안. 할 일 순서(`/api/tasks`·`/api/briefing/rank`)·몰린 주 경고·브리핑의 할 일 3개·미룰 것(오늘 몫이 나뉜 것 중 여유가 가장 많은 것)·카드 `today`가 모두 이 셈을 쓴다.
- 화면 세션 쪽지 `261111-2254_AI_밀도-날마다-몫-주소.md`: 패치의 `density.js`는 빼고 이 값을 그리면 된다.
- 쪽지 3번(모임 시간표 후보)은 규칙으로 서버 세션이 만들 몫이라 AI는 하지 않는다.
- 컨셉 소통판 22:36 참고도 처리: 시간표 사진 저장 때 그날부터의 eTL API 수업(`api-class-`)을 지워 두 번 보이지 않게(TT Wizard 넣기와 같게).
