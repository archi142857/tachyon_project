# Tachyon-화면-11 · 폰 고침 둘 — 고리를 누를 때 파란 칸, 시각 칸 첫 누름에 창이 움직임

- 도구: Claude (claude.ai, Claude Opus 5.5) — archi142857 쪽 '화면'(Frontend) 세션. 코드는 Vite + React, 확인은 Vitest·헤드리스 Chrome(Playwright, 폰 터치 흉내)
- 기록 유형: 사용자 직접 지시(버그 알림)
- 목적: 실사용 날 폰에서 본 두 가지를 고친다.

## 프롬프트 원문

````text
고리에서 일정 터치할 때 저런식으로 파란 네모박스가 뜬
````

````text
시간 수정하려고 눌러도 저런 식으로 한 번 팝업창이 위로 올라간 후 시간 다시 눌러야 수정이 됨
````

(사람이 붙인 그림 둘: 폰 '오늘' 하루 고리에서 일정을 누른 뒤 파란 네모와 글자 고르기 손잡이가 뜬 모습, '일정 고치기' 창이 위로 올라가 '끝' 칸만 테두리가 진해진 모습. 실제 일정 이름이 보이는 그림이라 저장소에는 넣지 않았다.)

## 결과 요약

- **고리 파란 칸**: 폰 브라우저가 누른 칸(넓은 SVG 구간)에 누름 표시를 그리고, 길게 · 두 번 누르면 가운데 글을 골랐다. 고리 카드에서 글자 고르기 · 길게 누르기 메뉴 · 누름 표시를 껐다(`styles.css` `.ring-card, .ring-wrap`). 일정 고르기는 그대로.
- **시각 칸 첫 누름**: 디자인 다섯째 묶음 ⑤의 `dialog.sheet.front:has(.input:focus)`(폰에서 칸에 초점이 가면 창을 위로)가 날짜 · 시각 칸에도 걸려, 누르는 순간 창이 움직여 시각 고르기 창이 안 떴다. 새 `web/src/lift.js`: 글자판이 뜨는 칸(글 · 숫자)에 처음 초점이 갈 때만 `.lifted`로 올리고, 창이 열린 동안 그대로 둔다. `Sheet.jsx` · `MemoPopup.jsx`(메모 즉시 확인)에 붙이고 `feedback1113.css`의 두 줄을 `.lifted`로 바꿨다.
- **확인**: 폰 390(터치 흉내) 예시에서 일정 고치기 창 끝 시각 칸을 눌러도 창 그대로 · 초점은 시각 칸, 이름 칸을 누르면 위로, 그다음 시각 칸은 그대로. 메모 팝업 고치기도 같음. 고리 가운데를 두 번 · 세 번 눌러도 골라진 글 없음. web 시험 180, 네 크기 셸 문서 스크롤 0.
