## 정한 것

- ALTER 다섯에서 룸메이트를 빼고 넷: 🧑‍🏫 튜터(핵심) · 🧭 조언자 · ✍️ 편집자는 사용자의 AI 앱이 맡고, 📚 사서는 Tachyon(서버)이 맡는다. 규칙(PLAYBOOK)과 튜토리얼은 `study_rooms` 답에 실어 보낸다 — AI 앱마다 따로 설정할 것이 없다.
- 방 = 이번 학기 eTL 과목 하나. 만드는 단계 없이 eTL만 이어 두면 목록에 바로 보이고, 처음 열 때 `study` 표에 줄이 생긴다.
- '빼먹지 않기'는 AI의 말이 아니라 코드가 막는다: ① 시험과 범위를 정하기 전엔 phase 'scope'(새로 올라온 자료도 '미정'으로 다시 묻게), ② 범위 안 자료의 모든 쪽을 읽어야 지도를 저장, 모델이 빠뜨린 쪽은 읽은 것으로 안 침, ③ 모든 쪽이 개념이나 '건너뜀(이유)'에 들어가야 지도 저장, ④ 범위 안 개념이 다 ✓여야 'done'. 범위에서 빼는 길은 `study_set_scope` 하나(사용자가 말했을 때만).
- 자료 읽기: 요약은 내용을 빠뜨린다(11-10 실측, 소통판 11-10 17:53) → 빠른 모델(Haiku)이 쪽마다 그대로 옮겨 적고 그 글을 사용자의 AI 앱이 읽는다. 파일은 Worker가 받지 않고(무료 요금제 CPU), eTL 내려받기 주소의 리다이렉트만 따라가 파일 저장소의 짧게 사는 주소를 Claude API에 넘긴다. 파일 · 옮긴 글 · 주소는 저장하지 않는다.
- 못 읽는 형식(pptx · hwp · 영상 …)은 지도에 '못 읽음'으로 남아 phase가 넘어가지 않는다 → 사용자가 채팅에 올리면 AI 앱이 직접 읽고 `by_client`로 지도를 낸다(또는 사용자가 범위 밖이라고 말함).
- 문제 순서: 다시 물을 때가 된 빈틈(✗ · △, 3문제 뒤) → 아직 한 문제도 안 낸 절의 첫 개념(진단) → 약한 절부터 안 본 개념 → 남은 빈틈.
- 시각화: 도구 `study_map`이 MCP Apps 창(시험 → 자료(주차) → 절 → 개념, 색 = 결과, 진도 고리, 다음 문제, 빈틈 · 안 본 것 거르기, 개념을 누르면 "튜터, … 문제 내줘")을 띄우고, 창이 안 뜨는 앱엔 같은 결과의 글 지도(`map_text`)를 준다.
- 비용은 팀 API 키: `study_read` 한 번 = Claude API 한 번(문서 전체가 입력). 하루 60번(`STUDY_READS_PER_DAY`)까지. 실제 토큰은 log `study_read`에 남는다(아직 실측 없음).
