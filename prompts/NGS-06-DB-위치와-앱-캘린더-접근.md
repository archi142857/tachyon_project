# NGS-06 · DB 위치 질문, 웹 + 앱, 캘린더 직접 접근

- 날짜: 2026-11-09
- 도구: Claude Code (Claude Opus 5.5) — 웹 조사는 Claude Code 하위 에이전트(웹 검색)
- 기록 유형: 사용자 직접 지시
- 목적: DB를 어디에 둘지 정하고, 웹과 앱을 함께 만들 때 캘린더를 직접 읽을 수 있는지 확인한다.

## 프롬프트 원문 (세 번에 나눠 보냄)

````text
좋아 그리고 일단 사용자가 적으니까 데이터베이스는 내 구글 드라이브에 올려서 쓰는 방식으로 하는거 어떻게 생각해?
````

````text
근데 용량이 충분해?
````

````text
앱과 웹 모두 만들려고 해. 참고하면서 작업해. 그리고 웹으로 키거나 폰/데스크탑 앱으로 켰을 때 캘린더에 직접 접근할 수 있는지도 봐줘
````

## 결과 요약

- DB: 구글 드라이브 대신 이미 만든 Cloudflare D1을 그대로 쓰자고 답했다. 무료이고, 동시에 쓸 때 기록이 사라지지 않고, 중복을 막는 유일 키가 있다. 용량은 사용자당 약 1 MB라 DB 한도(500 MB) 안에서 넉넉하다. 정작 한도는 하루 쓰기 10만 줄이라 수집기는 바뀐 줄만 쓰도록 계획에 적었다. (사용자 결정은 아직)
- 웹 + 앱: 화면 코드는 `web/` 하나로 두고, 같은 코드를 Capacitor로 감싸 안드로이드·아이폰 앱을 만든다. 데스크톱은 PWA 설치로 둔다.
- 캘린더 직접 읽기: 웹은 안 되고, 폰 앱은 공식 `@capacitor/calendar`로 된다(아이폰은 '전체 접근' 권한 필요). 데스크톱 앱은 사실상 안 된다. 구글 캘린더 API는 앱 검증 전엔 7일마다 로그인이 풀려 쓰지 않는다. 계정별로 다 읽히는지, 백그라운드로 읽히는지는 실기기로 확인하는 할 일로 넣었다.
